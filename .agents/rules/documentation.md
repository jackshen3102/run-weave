# 文档治理

本文决定 Runweave 文档**值不值得写、放在哪里、何时删除**。目标是让人和 Agent
都能按需找到当前真相，而不是扩大文档数量。

## 先判断是否值得写

满足任一条件时，内容才进入长期文档：

- 不知道它会造成错误决策，例如运行时边界、依赖方向、协议语义和验收入口。
- 事实不在代码中，例如设计取舍、运维约定或外部系统约束。
- 内容长期有效，且有明确代码或命令可以复核。

代码和 Git 已能表达的实现细节只链接入口，不在文档中复述。一次性计划、评审、
排障记录和截图不是当前事实，不得混入架构文档。

## 放置规则

| 内容                                 | 默认位置                                                          |
| ------------------------------------ | ----------------------------------------------------------------- |
| 全仓代码地图、跨运行时边界           | `docs/architecture/`                                              |
| CLI、部署、质量、测试的当前合同      | `docs/cli/`、`docs/deployment/`、`docs/quality/`、`docs/testing/` |
| 某个运行时或包的入口、边界、验证命令 | 目标目录的 `AGENTS.md`                                            |
| 某个运行时或包的长期详细设计         | 目标目录的 `docs/`；只有确实跨运行时才放顶层 `docs/architecture/` |
| 正在执行的计划或评审                 | `docs/plans/`、`docs/review/`，仅作临时过程材料                   |
| 已完成的一次性可视化产物             | `docs/architecture-flows/`、`docs/prototypes/`，必须标明历史属性  |

同一事实只保留一个权威来源。上层入口只说明“何时读什么”，不得复制下层正文。

## 渐进式披露

- L1：根 `AGENTS.md` 与 `docs/README.md` 负责路由。
- L2：目标目录的 `AGENTS.md` 或文档分类 `README.md` 负责领域地图。
- L3：具体设计、操作指南、测试计划和源码入口按需读取。

不要在根入口维护可由文件系统查询出的完整模块清单。查就近规则使用：

```bash
git ls-files '**/AGENTS.md' 'AGENTS.md'
```

## 生命周期

- 活文档描述当前事实；实现或命令变化时同一改动内更新。
- `docs/plans/` 与 `docs/review/` 在任务完成后删除；仍有效的结论先迁入活文档。
- 历史原型和架构流程不得被当作当前实现依据；需要当前事实时回到活文档和代码。
- 新增或移动 Markdown 后运行 `pnpm docs:check`，修复相对链接与缺失入口。

## 就近 `AGENTS.md`

只写本目录特有且容易遗漏的内容：

- 职责与非职责；
- 关键入口和真实调用链；
- 依赖方向或放置决策；
- 最小验证命令；
- 指向详细文档的链接。

不得复述根规则、源码实现或通用最佳实践。子目录规则可以收紧上层约束，不得放宽。
