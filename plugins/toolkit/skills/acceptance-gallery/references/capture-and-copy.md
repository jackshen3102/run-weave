# 取景与配文

## 问题决定素材

| 要判断什么       | 最少材料                               | 容易误读的地方                               |
| ---------------- | -------------------------------------- | -------------------------------------------- |
| 布局、控件可见性 | 目标区域及所属区域的定位锚点           | 切掉上下文后看不出位置；大块空白压缩关键文字 |
| 遮挡、安全区     | 遮挡物、目标及相关边缘同时入画         | 只截可见部分，无法判断是否仍被覆盖           |
| 状态变化         | 同一对象的前后图，说明改变了哪些条件   | 不同窗口或宽度不能直接当作修复前后           |
| 多步流程         | 入口、关键分支、结果，2–4 张关键图     | 离散截图不证明连续动作或实际时长             |
| 保存、重启、恢复 | 可见结果与真实事件、身份或状态核对记录 | 成功提示或终点图不证明持久化                 |
| CLI、API 或后台  | 可复制的真实结果文字与来源             | 不需要截成很长的终端图片                     |

页数由问题决定，不用“必须三张”一类数量目标驱动采集。需要判断重复稳定性时保留尝试条件和次数；没有这类证据就保留缺口。

## 截图如何放

原始图片保持字节不变。`crop` 仅设置阅读器显示窗口，完整原图仍可打开。第一版只允许 PNG 取景，JPEG 可完整展示；JPEG 的 EXIF 方向可能与像素坐标不一致，需要取景时在原界面重新采集 PNG，不修改或补画原图。

在实际阅读尺寸检查关键文字。太小则缩小取景范围或拆页；不要为了整齐强行把所有图片压进相同尺寸。竖屏原图保持比例；宽图对照在手机上上下排列。图外“看这里”应指向可辨认的具体对象，不重复描述整张图。

对照前核对目标、运行端、版本、尺寸与条件；不同条件必须说明。有结果图但没有前图时退回单图，不能生成假前图。需要真实运动或闪烁证据的任务不以截图模板替代原采集方式。

## 文案如何写

标题说明本页要核对的结果；建议 12–24 个中文字。正文以 1–2 句交代“条件、动作、实际观察”，建议 40–100 字。软长度目标不覆盖准确性要求。

- 历史关注区案例：写“A 已从关注区移出，但仍在下方项目列表中”；不写“A 被删除”。到期 fixture 不等于真实等待一小时。
- 历史配置案例：只有配置截图就写“当前显示四角色配置”；有受控重启、接口和文件哈希记录才可以写“重启后仍保留”，并链接相关记录。
- 历史跨端案例：两端显示相同状态可比较表达；没有匹配终端和事件身份时，不写“同一任务同步成功”。

`observed` 只表示有观察材料，观察到的也可能是失败；不要将它渲染或措辞为业务通过。`insufficient`、`not-run` 配合本页具体缺口。通用环境边界放任务说明，直接影响本页判断的缺口放本页正文或 limitations。

截图事实、记录事实和推断要可区分。文案校对时对照原图和来源逐页检查；生成器不会替 Agent 判断结论真假。不要复制凭据、环境变量全集或无关日志。
