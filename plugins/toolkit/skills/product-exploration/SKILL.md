# 产品探索

围绕用户指定目标发现值得处理的问题，不建立回归测试资产。终点是有证据的报告，修复另行确认。

## 启动与范围

- 只在用户明确要求本轮探索时执行。修改代码、提交、PR 或普通“修复这个 bug”不构成探索授权，不接自动触发 Hook。
- 用户只需提供功能或用户目标，例如“检查文件搜索体验”。先从任务上下文、必要代码和项目入口理解预期；不要求填写表格、编写 YAML 或提供测试步骤。
- 简短确认本轮目标、环境、数据权限和预算。已有上下文明确的内容不重复提问；目标或资源归属不清时，先问一个关键问题。
- 自主选择相关路径，不全仓扫描、不扩大到无关功能。偶遇范围外问题可简记为待确认，不展开调查。

## 环境与权限

- 浏览器探索使用同插件的 [playwright-cli](../playwright-cli/SKILL.md)，先读取其完整指令并遵循页面、Profile、附着和 detach 规则。工具不可用时报告阻塞，不拿静态阅读代替真实操作。
- 可复用已确认身份的真实环境。需要操作 Runweave Dev Session 时，先读取并使用 [runweave-dev-session](../runweave-dev-session/SKILL.md)；不得按旧端口、窗口外观或 ambient endpoint 猜目标，不默认升级为完整打包。
- 只做必要的环境准备，不趁机修基础设施、安装整套 Test Agents 或扩充工具权限。没有新的诊断线索时，不反复重试同一个准备失败。
- 真实数据默认只读。写操作只作用于可证明属于本轮的临时数据；更改真实数据或账号配置、发布提交内容、发送消息等外部动作，须单独说明对象和影响并取得授权。
- 写操作归属或副作用不确定时，先停下该路径请求确认，或继续独立的只读路径。不得为了复现重复制造有风险的副作用。
- 探索权限不包含修改产品源码、自动修复、提交 issue/PR、推送代码或调整现有测试预期。

## 时间与探索策略

默认探索上限 **30 分钟**，用户可覆盖或追加。环境准备时间单独记录，不计入探索预算。

页面可操作、开始探索时读取时钟，记录开始时间和截止时间；进入新分支或长耗时操作前检查剩余时间。合理限制单次等待，不依靠固定 sleep 推进。到期后不展开新路径，在安全点结束操作并完成报告、清理；说明实际耗时和超时部分。Skill 不是计时器或安全沙箱，不能保证强制中断工具，也不替代宿主权限控制。

优先顺序由用户目标和现场观察决定：

- 先走一条核心用户路径，确认用户是否能完成目标。
- 根据暴露的状态转换和风险，选择相关的空数据、边界输入、取消返回、重复操作、错误恢复等分支。不是固定清单，不必逐项执行。
- 异常出现后收窄复现步骤，区分用户可见失败、预期不明确与工具/环境问题；只读查看必要代码、控制台或网络证据帮助解释，不修产品。
- 等待可观察的业务状态，优先语义定位和可重试断言；不用强制点击、mock 或 DOM 状态注入把失败路径改成成功。确需模拟环境条件时，限定自有环境并明确证据限制。
- 一条路径失败不要求停止整轮；可以继续独立且在范围内的路径。预算耗尽、没有高价值新路径或无法安全继续时结束，不为凑数量或用满时间继续消耗。

可使用内存中的自动化片段或本轮临时脚本帮助操作和取证；不生成持久化测试代码、`*.spec.*` / `*.test.*`、YAML 测试计划或 CI 配置，不把临时动作包装成需要维护的测试套件。执行固定验收合同是另一项任务，不自动转入 `run-test-cases`。

## 结论与证据

将观察分开报告：

- **已确认缺陷**：通过真实操作发现并安全复核至少一次；有明确预期依据、实际差异和用户影响。附最短复现步骤、复核结果、必要证据及建议。
- **待确认疑点**：未复现、不可安全复核、预期不明确或仅有代码推测。说明还缺什么证据，不给出确定的缺陷结论。
- **体验建议**：说明如何妨碍用户完成目标及建议理由，不把个人审美偏好作为功能错误。

取证前缩小范围，优先裁剪或遮罩无关真实数据；不落盘或输出凭证、Cookie、Token、完整敏感响应、无关个人信息。可读取不等于可导出或发送。无法安全保留证据时只描述现象，并标注证据限制；不默认上传外部平台。

交付简短中文结论和本地报告，默认保存在 `artifacts/product-exploration/<本轮唯一标识>/`，只留报告和必要证据，不留需要维护的执行代码。报告按实际发现组织，不强制每类有内容，包含：

- 本轮目标、实际环境、数据权限、准备与探索耗时；覆盖了什么、哪些未覆盖及原因。
- 按用户影响排列的缺陷、疑点和建议，各自附对应证据或证据限制。
- 清理结果、仍需授权或后续确认的事项。

没有发现问题就如实报告；未覆盖不等于通过，不宣称完整验收或产品“没有 bug”。最终报告后停止探索，等待用户决定是否修复或继续。

## 收尾

关闭本轮自建终端、删除本轮临时数据和执行文件，仅操作已核实归属的资源；停止本轮创建的 Dev Session 并 detach。已有用户会话、真实目录、账号配置与 Cookie 保持原状，不为“隔离”或“清理”而重置它们。

失败、中断或预算耗尽时也应尝试安全清理；无法清理则明确列出遗留资源和原因，不声称已清理完成。报告和经过最小化处理的证据可以保留。
