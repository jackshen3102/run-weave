# 复杂任务拆分与验收续接

主 Agent 持有用户目标、关键决策和最终验收。复杂任务开工或出现新的独立步骤时，按当前任务和可用子 Agent 的职责判断分派。在宿主能力和现有授权允许时，符合条件的步骤尽早分派，用户只描述目标也适用。主 Agent 同时推进不依赖该结果的工作。

## 何时拆分

默认由主 Agent 直接执行。主动分派前，确认子任务有明确输入和可独立核对的结果，并且下列至少一种收益足以抵消交接和复核成本。

- **中间输出量大。** 大范围代码搜索、长日志或测试输出可留在子会话，主 Agent 只接收结论和证据引用。单个这样的子任务也适合分派。
- **有可并行的独立工作。** 例如调查互不依赖的模块，或用不同隔离实例验证各自的场景。按任务边界分派，能独立完成的工作并行推进。
- **需要专门工具或独立判断。** 分派能提供主会话当前缺少的工具约束或判断独立性时，选择职责匹配的子 Agent。用户指定 Runweave 独立代码 Review 时使用 [review-agent](../review-agent/SKILL.md)。

随手能完成的小改动、需反复和用户对齐的步骤，以及必须持续共享大量上下文的工作，留在主会话。依赖同一个终端、页面、设备或可变状态的操作交给同一执行者顺序完成。宿主无子 Agent 能力或当前授权不允许分派时，主 Agent 按同一验收记录继续。

## 分派与保留验收状态

给每个子 Agent 一份能独立执行的任务说明，包含目标、必要输入及版本、读写或运行资源范围、预期交付和完成条件。优先引用原始资料，只附需要的上下文。并行写入须划清文件和资源归属。让子 Agent 回传实际结果、所测版本、证据位置及未验证项，原始日志等大输出留在可回读的位置。

主 Agent 在分派前把当前有效的用户要求、验收项、版本和负责人记在已有计划或任务证据目录。每次收到结果、用户改范围或版本变化时及时更新，保留已通过、失败和待验证项及对应证据。没有现成记录且任务有压缩风险时，创建一份简短的本地任务记录并保留路径。

上下文压缩、恢复或交付前，先读该记录和后续用户修订。按 [acceptance](../acceptance/SKILL.md) 回查关键证据，只重验受版本变化影响的部分，继续完成待验证项。主 Agent 按用户要求判断全局交付是否完成，子任务结束只更新其对应条目。
