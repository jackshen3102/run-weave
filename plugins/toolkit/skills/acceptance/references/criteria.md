# 目标与证据核验

## 条件与来源

为每项承诺指出用户来源、可观察结果和适用端或入口。按用户修订的时间与意图确定
当前范围；普通继续不取消原条件，已结束的旧任务不因出现在资料中重新变成义务。
只写计划时核对正文，不执行其中未来步骤。不要求四份规格或创建新的反馈台账。

## 证据适用性

逐项记录版本、实际入口、动作、预期、实际与原始证据。未提交代码用相关 diff/内容摘要，
安装态用实际构建，设备操作记真实设备。文件存在、模型声称通过、构建或安装成功只支持
各自覆盖的结论，不证明整个用户目标达成。

相关代码、配置或构建取证后变化，重验受影响项；未受影响证据说明适用性后可复用。
全仓 HEAD 变化不自动使全部证据失效。回归按变更调用链选择，不扩大到无关全仓验证，
不新增单元测试。浏览器、iOS、用例与 Dev Session 操作分别沿用对应专属技能。

用户要求真机时，桌面窄屏、模拟器和截图不能替代真机操作。真人确认仅在明确要求、约定
流程或主观判断依赖用户时保留；User Agent 不代签，不给确定性任务追加审批。

只有全部必要条件有适用证据且无未处理反证时，才能报告目标达成。

## 受阻判定

对同一障碍，必须实际尝试至少 5 种实质不同的解决方案，全部失败且有证据，才可将该项记为“受阻”或 `blocked`。首次报错后，根据错误和现场状态选择可行的恢复路径，优先尝试成本低、能验证当前判断的方案。任何一种奏效就立即重跑原场景并继续剩余工作；第五次失败若揭示了可行的新路径，继续处理。

每种方案记录采取的动作、它改变了哪个条件或采用了哪条独立路径、实际结果及证据。原样重试、改写同一条命令、仅列出备选方案都不能凑数。方案沿用原目标、指定环境和已有授权。例如真机验收可以修复真机连接或改用另一条受支持的真机连接路径，模拟器结果不能计作真机恢复尝试。

五种均失败时，报告受影响的验收项、五种尝试及证据、恢复所需的最小条件，继续完成其余独立项。如果现有授权内可行的恢复路径已经用尽，剩余步骤必须由用户授权、解锁设备或作出取舍，请求该具体动作并如实记录已尝试的数量。少于五种时保留该项待继续，不能据此宣告受阻。
