# 目标与证据核验

## 条件与来源

每项条件包含局部编号、用户来源、可观察结果和适用端/入口。按用户修订的时间与意图确定
当前范围；普通继续不取消原条件，已结束的旧任务不因出现在资料中重新变成义务。
只写计划时核对正文，不执行其中未来步骤。不要求四份规格或创建新的反馈台账。

## 证据适用性

逐项记录版本、实际入口、动作、预期、实际与原始证据。未提交代码用相关 diff/内容摘要，
安装态用实际构建，设备操作记真实设备。文件存在、模型声称通过、构建或安装成功只支持
各自覆盖的结论，不证明整个用户目标达成。

相关代码、配置或构建取证后变化，重验受影响项；未受影响证据说明适用性后可复用。
全仓 HEAD 变化不自动使全部证据失效。回归按变更调用链选择，不扩大到无关全仓验证，
不新增单元测试。浏览器、iOS、用例与 Dev Session 操作分别沿用对应专属技能。

用户要求真机时，桌面窄屏、模拟器和截图不能替代真机操作。真人确认仅在明确要求、约定
流程或主观判断依赖用户时保留；User Agent 不代签，不给确定性任务追加审批。

## 报告与返回

普通对话优先直接报告；已有报告时复用它，不复制台账。按需要使用下表：

| 条件及来源         | 预期       | 实际与结论                        | 证据及版本适用性       |
| ------------------ | ---------- | --------------------------------- | ---------------------- |
| 实际用户条件与来源 | 可观察结果 | 已验证/发现失败/尚未验证/用户取消 | 实际证据位置及适用范围 |

以上是内容模板，不是新协议。宿主合同优先：专门 Review 使用 checks 记录逐项目标核验，
每项说明来源和证据；取消或延后事项在 summary 说明用户来源并排除，不作为 checks 中的未验证项。
limitations 只保留影响当前必要条件的范围、环境和未执行缺口，不恢复已取消义务。
只有已复现的代码 Bug 进入 findings，需求不明或证据缺失本身不是 Bug。

任务 completed、输入 received、代码零发现、反馈清零或报告接受均不代表目标达成。只有全部
必要条件有适用证据且无未处理反证时，才能报告目标核验完成。没有可核对的用户要求时，
明确本轮只审代码，代码覆盖完整可以结束代码审查，不能据此声明用户目标完成。核验者返回事实、影响和缺口，
由调用方处理返工；本技能不自动发布、发消息、关闭待办、制作材料或登记其他任务。
