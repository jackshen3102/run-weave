# RemoteDesk macOS

- 独立 macOS 15+ 原生 App，采集与输入不进入 Backend / Electron；只依赖 Apple 框架与本地 Swift 协议包。
- 最终部署与权限验收使用 `build-host.sh` 产出的 `.app`。开发编译、签名、启动、授权、真实会话是不同证据层。
- 更新使用根目录 `pnpm host:update`（包内 `update-host.sh` 为同一入口），由 Agent 独立构建并验签后部署到固定 `/Applications/RemoteDesk.app`，正常退出旧进程、启动新版服务并读取 JSON 回执；已安装时沿用签名团队和保存的接口，首次指定 `--team TEAM_ID --interface INTERFACE`。启动不依赖界面自动化，正常流程不要求用户点击按钮；失败时先按回执排查，仅将无法自动处理的阻塞交给用户。
- 更新只部署 Release；所有 checkout 共用更新锁。失败回退与旧服务恢复单独报告，回退成功不等于更新成功；日志、备份和异常锁处理见 [README](README.md)。
- 未收到启动或更新指令时默认停用服务；仅监听所选物理 LAN IPv4 接口，配对不自动开始屏幕采集或输入。
- 用户要求更新 Host，即授权完成构建、部署、启动新版进程和局域网服务，并验证实际连接；除非明确要求只构建或更新后保持停止，不重复询问是否启动，也不把启动步骤留给用户。仅构建成功或旧进程仍在运行不算更新完成；若启动受阻，说明具体工具或系统阻塞及尚未完成的步骤，不能把“必须由用户点击启动”作为更新限制。
- 不导入 launchd、公网端口映射、Tunnel、音频、剪贴板、文件或 shell 能力；不更改 TCC / SIP / AMFI。
- TLS 1.2+、精确证书 pin、有效期、唯一 trust anchor 与系统 SecTrust 评估缺一不可。长期身份和设备令牌仅存独立 Keychain service。
- 默认只读配对；本机用户分别批准观察/控制。撤销和停止立即失效会话，输入 lease 超时必须释放。
- 编码、发送与采集队列必须有上限。丢弃依赖帧后等待含 SPS/PPS 的 IDR；不得把 P 帧断链当成正常恢复。
- 不新增单元测试。手工协议探针用 ignored 输出目录；UI/真机验收由主 Agent 执行，未执行不得声称通过。
- 修改上游衍生文件同时维护来源与 MIT 许可。默认仅 Mirador 的本次精确 SHA 可进入导入范围。
