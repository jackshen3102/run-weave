闭环的边界：后台能自动生成候选；检索、采用和结果反馈仍依赖 Agent 执行 skill。安装了入口，不等于每次都会检索，也不等于一定产生有效反馈。

任务状态：分析是否执行完

queued→running
  • completed 分析结束；候选可能入库，也可能仍待补充或被拒绝。
  • skipped 无新发现、缺少配对工具结果，或事实已处理过。
  • failed 读取、模型调用等执行异常；修复原因后通过 CLI retry 重试。
  • 正常关闭会取消进行中的分析并重新排队；崩溃后等 5 分钟租约到期，再次领取。

候选状态：是否进入推荐库

pending→promoted
  • supported：模型认为有支持证据，还需通过证据有效性与数据库版本检查。
  • insufficient：材料不足，保持 pending；不进入检索结果。
  • contradicted：存在反证，进入 rejected。
  • pending 不会仅因等待而自动重试。补齐验证后可显式 save；后续新任务也可重新提炼。

经验状态：现在是否可检索

active→needs_revalidation
  • 可推荐须同时满足：active、未过期、证据校验通过。
  • 当前版本收到带证据的失败回执 → 生成待复核的新版本，停止推荐。
  • 旧版本迟到的失败只进入历史，不直接停用新版；单纯 dismissed 不全局停用。
  • retired 或过期也不推荐。自动生成经验默认 30 天有效，成功回执不自动续期。

哪些数据放在哪里

~/.runweave/experience/
  <namespace>/
    _queue/store.sqlite       ← 跨项目任务队列
    <repositoryId>/
      store.sqlite           ← 项目经验与反馈
      evidence/*.jsonl        ← 引用的事实摘录

SQLite 中保存记录、旧版本、查询凭据、反馈与候选；Activity 另行保存原始事件及内容。经验归档只保留引用范围的摘录。

身份与版本怎么区分

  • repositoryId：Git common directory 规范路径的 SHA-256；worktree 共用，端口不参与。
  • namespace：默认 production / beta / development；可由 Backend 启动配置覆盖。
  • revision：经验内容版本；更新必须对上旧版本，防止互相覆盖。
  • lookupId：一次查询实际返回的 id + revision。反馈必须引用其中的记录。
  • 独立 clone、移动主仓库会改变身份；当前没有跨机器自动合并。
三种“完成”不能混用：用户任务完成 ≠ 学习任务 completed ≠ 候选 promoted；promoted 也不等于实际使用已证明有收益。

建议你沿这些边界检查设计

下表描述现有行为和明确限制，不把每一项都当作缺陷，也不代表本轮要继续改代码。

检查点当前实际行为意味着什么
未安装 skill 会怎样？没有这套 skill 的按需检索入口；Stable 后台学习仍默认开启，可用环境变量关闭。skill 安装和后台学习是两个独立开关。桌面不会安装、更新或补装该 skill。
Pi 会话如何学习？普通 Codex / Pi 的完成事件都可触发；提炼和复核统一调用已登录的本机 Codex CLI。仅安装 Pi 或 skill 不足以完成自动学习，还需要 Backend、hooks、Activity 和 Codex Provider 可用。
检索有多“智能”？目前是关键词触发组匹配：组间 AND，组内 OR；不是向量检索或模型语义检索。不同说法可能漏召回。最多返回 3 条；未命中时继续正常排查，不跨项目兜底。
失败后能自动恢复吗？当前经验失败会暂停推荐；后续新事实可重新提炼，或经验证后显式 save。没有定时重新验证所有经验的流程。failed 任务可手动 retry；pending 候选不能靠 retry 直接恢复。
证据能无限保存吗？学习单内容最多 40,000 字节、单轮 160,000 字节；读取最多 50 × 200 条。归档每项最多 64 KiB。源内容过期或超限会明确失败。原文件删除可用归档；原文件仍存在但内容改变会停止推荐。
会不会因日常改代码失效？不会因源码哈希变化而排除；codePaths 只是可选提示。Agent 仍要核对当前版本、配置和环境。可召回不等于当前条件已经满足。
历史是否按最近几天滚动？尚未实现滚动查询或自动清理。状态接口展示最近 50 个任务，但内部仍读取历史任务。当前测量没有性能改造必要；将来若限时，应限制已完成历史，不能漏掉待处理和待重试任务。
还有哪些已知限制？多行和嵌套 JSON 脱敏遗漏按约定暂未处理；模型复核依然可能判断错误。复核支持是建议性判断，不是独立事实认证；页面不把它包装成已证明的业务收益。

已经验证过的变化

① 修改源码后成功、失败和旧版本回执：原先 3 次失败，现在 3 次可保存。② 本轮与历史反证被遗漏的两种复核场景：原先晋级，现在拒绝；补齐实际恢复证据后可晋级。③ 后续追加 201 条事件：新旧任务都能恢复原轮次。
