RUNWEAVE / 核心架构流程

把家里的 Mac 带在口袋里

手机负责下指令，Devbox 负责中转，代码与 Agent 始终在 Mac 上。

实测方案快照 · 2026.09.25
SSH 建连方向：Mac → Devbox指令方向：手机 → Mac输出方向：Mac → 手机
2

手机访问 Devbox，指令最终交给 Mac

App 向 Devbox :15443 发送 HTTP 请求。中转程序把流量送到 Devbox 自己的 :15444，再沿 Mac 已建立的 SSH 隧道回到 Mac :15445。网关交给 :5001 Backend，校验登录身份后，把输入送入本地终端。

“反向”说的是监听位置

SSH 由 Mac 发起，却在 Devbox 上开一个端口，通向 Mac 本地服务。连接建立后，隧道可以双向传输数据。

手机是客户端，Mac 持有进程

手机退出，只是暂时失去观察和输入通道。tmux 与 Pi 仍在 Mac 运行；回来重新连接，就能读取结果并继续输入。

三个地址，三个职责

15443 负责接入，15444 负责反向转发，15445 负责网关过滤。每台机器的 127.0.0.1 都只指向它自己。

展开：ssh -R 怎么读，以及真正发送的接口
# 在 Mac 上运行（概念化写法；替换 Devbox 主机名）
ssh -N -T -o ExitOnForwardFailure=yes \
  -o StrictHostKeyChecking=yes \
  -o ServerAliveInterval=15 -o ServerAliveCountMax=3 \
  -R 127.0.0.1:15444:127.0.0.1:15445 user@devbox

# -R  [Devbox 监听地址]:[Devbox 端口]:[Mac 目标地址]:[Mac 目标端口]
# 手机输入：POST /api/terminal/session/{id}/input
# 终端输出：WebSocket /ws/terminal
15443 · Devbox绑定指定内网 IP；供手机访问。
15444 · Devbox仅回环；由 SSH -R 创建监听。
15445 · Mac仅回环；拦截内部路由、保留原鉴权。
5001 · Mac已有 Backend；复用终端与项目协议。

SSH 加密的是 Mac ↔ Devbox 这一段。手机到 Devbox 当前使用内网 HTTP，外出方案依赖可访问该内网的受信任 VPN；尚未配置 HTTPS。Mac 休眠、Backend 停止或隧道失效时，手机入口也会不可用。

实测通过：手机经中转发送指令与读取回复 · 重启 App 后继续原会话 · 手机后台期间 Mac Agent 完成任务后回读。
验证边界：iPhone 17 / Wi-Fi / USB 自动化；蜂窝 + VPN 未测。当前为本机可行性实例，尚未配置开机或登录自启动；Mac 休眠与长期稳定性未测。
