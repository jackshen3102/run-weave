01
首次审计实现 · verdict.ts · continuationPrompt

让“继续”真正启动下一步

持续推进的价值来自下一项工作被完成。状态说明只应服务于行动；不能让结束回复成为工作本身。

原问题
固定模板要求“仅问询、不构成执行指令”，Agent 因而只报告状态。
本轮改变
续接现在携带当次 remainingWork 和 nextAction，要求原会话执行已有授权内的下一步并报告新增结果。
记录依据
17f6ccb4 / 2cc72439：本地验收无阻塞，连续回复“状态未变”。
保留边界
不接管原执行器，不启动替代任务；原用户的只读、停止、等待确认优先。
02
首次审计实现 · classifier.ts / shared/task-supervision.ts

把已有授权带进每一次续接

授权应随用户范围变化，而不是每一轮清零。重复确认增加打断，却没有增加任何决策信息。

原问题
“提醒不是新增授权”被错误解释为“此前授权不再有效”。
本轮改变
分类必须给出真实用户消息 ID；程序拒绝把 assistant 或监督输入当作授权来源。续接明确已有授权持续有效。
记录依据
5f4da215 → f4cd2418：无环境阻塞却等待再次确认。
保留边界
引用合法只证明来源存在，不能机械证明语义授权；不会替真实审批点击同意。
03
首次审计实现 · classifier.ts / journal-schema.ts

受阻必须写出依赖和最小解锁动作

能说清谁提供什么才能继续，才有可操作的阻塞。审批、设备、私有信息与习惯性问句应分开。

原问题
分类容易直接相信“需要确认”，没有说明究竟缺什么。
本轮改变
blocked 输出须有 remainingWork、blocker、requiredUserAction；缺字段或非法来源拒绝该结果。
记录依据
13 条 blocked 已逐条复核，3 条手机连接与 2 条同一外部服务记录有必要依赖。
保留边界
不会为了让状态好看而将真实设备或账号依赖改成 continue。

整体任务受阻需要所有有效路径都受阻。能够拆开的工作应先推进，但不能凭空假设工具可绕过前置条件。

原问题
一个真机登录条件让整份本地验收停下来。
本轮改变
分类先核对是否有资料支持的独立必要步骤；有则输出具体行动，外部条件留在剩余项。
记录依据

首次审计实现 · classifier.ts

控制任务范围，防止越做越难完成

错误扩范围和提前宣布完成是同一类问题：都没有稳定地跟踪用户到底要什么。

原问题
Agent 自拟样例或额外发布被当作必需项；旧 PR 指令也可能被无限延用。
本轮改变
明确按真实用户范围判断；自拟额外事项不增加义务，已完成的旧交付不自动授权新改动提交。已选计划的明确剩余项不能因输入缺文而消失。
记录依据
9e433c1a：研究被扩成样例制作；6014f710 链路：旧 PR 范围可能被延用。
保留边界
不把“未提供计划正文”当作完成证据；同一 thread 的语义任务切换仍是后续架构问题。
06
首次审计实现 · classifier.ts / verdict.ts

用可核对证据定位，取消僵硬复现口令

先有证据是正确的，证据必须只有一种形式则不正确。直接的输入反例往往比反复点击更可靠。

原问题
“未复现不得改代码”被读成必须再做一遍手工 UI 复现。
本轮改变
明确真实复现、确定性回放、可核对日志、代码反例均可支撑定位；正常实现无需先制造故障。
记录依据
原随记已提供滚轮输入链路证据，却仍在反复等待复现与授权。
保留边界
证据不足继续调查，修复后仍需验证；不把代码推测冒充实际 UI 通过。

首次审计实现 · verdict.ts / classifier.ts

重复汇报时，改变动作而非重复问句

同义改写不等于进展。额度应该用于改变事实；本轮先修复动作质量，保留现有三次资源上限。

原问题
三次自动输入把“无变化”问了三遍，随后耗尽额度。
本轮改变
续接附带本轮此前 observed 次数；分类结合真实前文要求直接推进或换有证据的路径，不得靠重复问询改判完成。
记录依据
165a5ff8 → df29ee0a → 17f6ccb4 → 2cc72439，三次已接收后本地验收仍未动。
保留边界
未新增确定性语义进度检测；没有新线索且外部确实不可恢复时停止，不无限续跑。

首次审计实现 · continuation.ts / delivery.ts / service.ts

修正运行时的两种假停顿

“还没做”“做了但不知道结果”“已完成”必须区分。输入保护可以阻止旧动作，不能凭空制造未知副作用。

原问题
投递前取消却记 unknown；分类开始就提交最终回复游标。
本轮改变
未调用投递即取消记 not_sent 并退回同轮额度；已开始投递仍 unknown。成功判定与去重游标同事务提交，失败后同一回复可再次处理。
记录依据
日志 5 次投递前 input revision 改变被记 unknown；隔离后端故障回放已验证修正。
保留边界
不重放真正未知的输入，不清空草稿，不把旧轮退款计入新轮；没有新增后台无限重试。

13 条“受阻”，不能一刀切地删除

手机断开、外部服务不可用是真实依赖；关键歧义和用户主动讨论保留决定权。最该消除的是无必要依赖却再次索要授权，以及把一部分工作等待扩大成所有工作停止。下表是人工复核判断，非模型自动标签。
