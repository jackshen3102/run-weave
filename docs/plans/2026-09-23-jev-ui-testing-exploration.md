# Jev 浏览器与 iOS 测试探索计划

日期：2026-09-23。状态：方案已整理，尚未执行实验。本文是临时探索计划，不是已实现架构或已通过的验收报告。

## 1. 交接目标与授权范围

用户希望研究 Jev 在以下场景的实际价值：

- 浏览器：排查问题、执行已有测试案例，以及围绕明确目标探索路径。
- 原生 iOS：Runweave 与随记各自的模拟器、以及两个 App 的真机测试。

核心问题：**在不降低结果可信度的前提下，Jev 能否通过接管局部操作决策，减少强模型参与次数、整轮耗时或费用，且适配成本可接受？**

当前用户只要求整理方案，后续交给其他 Agent；本轮不调用 Jev、不启动测试、不实现工具、不启动其他 Agent。后续 Agent 在收到执行指令后按本文开展有界实验；本文本身不授权生产数据写入、部署、提交、发布或永久平台建设。执行者无需依赖原聊天，但必须重新核对现场和当时适用的工具规则。

允许得出“不值得接入”“只适合部分场景”或“证据不足”的结论。不得把接入 Jev、跑通一个 Demo 或产出框架当作成功目标。

## 3. 方案选择与职责

候选路线包括旁路观察、局部执行、探索路径选择、异常筛选和完整执行循环。首轮采用“旁路观察 → 局部执行”的顺序；路径探索和完整循环仅在首轮证据支持后另行提出。异常筛选可作为旁路观察的一部分，不自动改变业务结论。

| 角色     | 职责                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 主 Agent | 理解需求；确定任务边界、候选分支和验收依据；处理歧义、视觉问题与根因分析            |
| Jev      | 根据当前相关状态，在合法候选动作中选择下一步，或要求重新观察、交回主 Agent          |
| 执行工具 | 使用当前目标和新鲜引用执行动作；拒绝过期、无效或越界动作；记录实际结果              |
| 结果核对 | 通过明确条件、实际 UI、必要的只读业务查询核对后置状态；语义或视觉结论保留证据并复核 |

已有案例的目标、必需步骤、输入和通过条件保持不变。自由探索允许选择分支，但必须另记探索路径，不能冒充原案例通过。根因假设交给主 Agent；Jev 的分类不能当作因果证据。

局部任务以“找到指定记录并进入编辑状态”一类有明确终点的短流程为单位。不要默认每点击一次都调用强模型，否则无法验证减少强模型往返的收益；如果现有工具必须由强模型逐步监督，则明确标为“辅助决策实验”，不宣称自主局部执行。

## 5. 分阶段执行

### 阶段 A：现场与基线

- [ ] 保存分支、HEAD、已有修改摘要和工具版本；保留用户工作区，不能直接更新主分支或重置现场。
- [ ] 核对五个目标：浏览器、Runweave 模拟器、随记模拟器、Runweave 真机、随记真机。两个 App 可使用同一真机，但操作必须串行并明确绑定 App。
- [ ] 选择每类一个短流程，登记输入、前置状态、测试对象身份、通过条件、独立核对方式和清理办法。真机优先复用模拟器所选业务目标。
- [ ] 先验证现有控制链路能取得真实 UI 状态；不可用的目标记 blocked。不得为运行 Jev 顺手修复产品或重建工具链。
- [ ] 使用当前流程测量准备、读取、模型判断、操作等待、核对与恢复的耗时；记录强模型调用数和人工介入。

输出：环境清单、基线记录、适用 Case ID、不可用项及原因。先判断模型决策是否为主要成本；若设备等待占主导，明确收益上限，不以 API 延迟代替整轮耗时。

### 阶段 B：旁路判断

- [ ] 默认准备 36 个已脱敏状态，浏览器、Runweave、随记各 12 个；覆盖正常、加载、同名目标、弹窗或键盘干扰、动作无变化、完成与信息不足。实际缺失的状态如实记录，不补造真实证据。
- [ ] 每份状态包含局部目标、相关控件、最近必要操作、合法动作及独立参考判断。参考判断允许多个合理动作；不能把另一个模型的输出直接当真值。
- [ ] Jev 只作建议，不控制设备。输入值由任务预先指定；不要求它生成文本、坐标、选择器或命令。
- [ ] 前 18 份用于调整描述，后 18 份冻结后评估；每种目标各占一半。冻结集不得边看结果边改规则；必须调整时记录新版本并另取未见样本。
- [ ] 核对动作是否符合任务、能推进目标、是否应当交回主 Agent；保留错误、歧义和调用失败。

进入局部执行的探索门槛：冻结集至少 16/18 个建议经复核可接受，且没有越界动作或错误完成建议。此门槛是本计划的试验筛选规则，不是产品可靠性指标。未达到时分析一次主要失败原因；仍不满足则停止对应路线并报告，不无限调提示词。

### 阶段 C：局部执行对照

- [ ] 浏览器和两个模拟器先各选一个短流程，每个流程做 3 对对照，共 18 次执行。每对从可核对的等价前置状态开始，交替 A/B 顺序。
- [ ] A 为强模型局部决策，B 为 Jev 局部决策；两者使用相同状态摘要、候选动作、工具、动作预算和结果核对。阶段 A 的现有流程另作参考，避免把上下文整理或工具改造收益全部归给 Jev。
- [ ] 如果流程无需语义判断就能由固定规则执行，记录这个更简单的替代方案，不人为增加模型调用。
- [ ] 每次局部执行上限为 20 个动作或 5 分钟，先达到者即停止；连续 3 次无进展或 2 次模型调用失败则交回主 Agent。等待策略按工具和页面状态确定，不忙轮询。
- [ ] 对明确结果单独核对；Jev 的 DONE 仅是完成建议。主 Agent 接管、重试与核对耗时均计入本轮，不能从成功时间中扣除。

浏览器和两个模拟器分别作决定，不要求一个平台失败就否定全部平台。小样本只支持探索判断，不计算有推广意义的成功率保证或 p95。

### 阶段 D：真机迁移

仅迁移对应模拟器上已完成阶段 C 且未出现错误通过或越界的流程。真机 UI 连接失败属于环境阻塞，不属于 Jev 的判断失败。

- [ ] 两个 App 各做 3 对对照，最多新增 12 次执行；单独保存设备、构建、连接方式和签名执行器的必要身份信息。
- [ ] 记录键盘、系统弹窗或前后台切换带来的差异；不得临时扩成一组全新复杂场景并与原短流程混算。
- [ ] 截图用于实际视觉复核；控件树可读不代表布局正确。树、前台 App 与截图冲突时交回主 Agent。
- [ ] 按既有工具规则收尾，只释放本任务拥有的资源。共享模拟器整段任务结束后 finish；真机不清理他人 runner 或用户 App 数据。

## 7. 错误处理与边界

- 模型只能选择当前候选动作，不能生成任意 shell、浏览器脚本、设备命令或未观察坐标。合法候选集合也不能代替用户授权。
- 执行前检查目标与状态是否仍适用；状态变化后重新观察，不能沿用过期引用。
- 保存等写动作超时或返回结果未知时，先通过 UI 和必要的只读业务查询核对，不能自动重发。
- 模型不可用、配额不足或网络错误分别记 provider failure。回退到主 Agent必须可见，计入成本，不把回退后的完成宣称为 Jev 独立完成。
- Jev 云端请求仅使用专用测试数据或脱敏最小摘要。不得直接发送真实会话、随记正文、凭据、完整日志或未审阅控件树；缺少合适数据或 API 凭据时报告具体阻塞，不寻找或输出秘密。
- 使用明确的专用测试服务与身份。真实数据默认只读；发现已有草稿或身份不明的数据时保留，不覆盖。不能为了恢复基线而卸载 App、擦除设备或删除用户数据。
- 本计划不新增单元测试、长期测试脚本、CI 门禁或业务修复。既有 YAML 按原合同执行；实验采样与对照方法只作为研究协议，不伪装成新的 Markdown 产品测试案例。
- 若必须新增产品验收合同，按仓库规则使用 YAML 并运行对应格式校验；不要以补齐测试资产为由扩大本轮研究范围。

## 9. 判定与交付

每个平台分别报告：独立核对后的完成次数/总次数、错误宣称通过次数、越界动作次数、模型及工具失败、接管次数、整轮耗时、费用，以及初次准备/适配耗时。未知费用写 unknown，不按其他模型价格估算。

至少报告全部尝试和逐对耗时；3 对样本可给中位数，但不足以推出稳定分布。冷启动、预热、前置状态恢复、安装构建分别标明，不能混算后只展示最快样本。

按以下标准给出结论：

- **值得扩大验证**：同一平台的 3 对均可独立核对完成，没有错误通过或越界；至少 2 对整轮耗时减少，且中位数减少至少 20%；或在耗时不恶化时总模型费用减少至少 30%。这是探索性的投入门槛，不是性能承诺，扩展前仍需更多样本。
- **局部可用**：仅部分流程满足上述条件，或仍依赖主 Agent 接管；写清适用范围，不能推广到整个平台。
- **暂不值得**：收益主要来自预先编排，适配/接管成本抵消收益，或简单规则可完成相同任务。列出实际成本，不仅写主观判断。
- **证据不足**：设备、服务、凭据、数据或核对手段阻塞，或者样本不足。不得把 blocked 记为 passed，也不得由此宣称 Jev 无效。

错误通过或越界一旦出现，停止该配置的自动局部执行，保留现场并分析；不能靠其余成功轮次抵消。没有发现未知缺陷不等于缺陷检出率高，未建立带标签故障样本时不得报告漏报率。

最终 `REPORT.md` 必须包含：原问题、实际范围与未执行项、模型/工具/源码版本、全部试验汇总、可追溯证据、失败归因的证据边界、资源清理结果、下一步建议。若研究结束，将有长期价值的结论迁入合适活文档后按文档治理规则清理本临时计划。

本轮文档验证：运行 `pnpm docs:check` 核对链接与文档约束；这不代表任何 UI 或 Jev 实验通过。
