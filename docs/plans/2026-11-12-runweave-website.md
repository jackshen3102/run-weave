# Runweave 官网首期实施计划

日期：2026-11-12。粒度：L2。状态：首期代码已实现并完成本地检查；正式部署待提供域名与托管位置。

## 1. 目标与依据

将已选定的米白官网设计实现为可访问、可抓取、适配手机的静态产品首页，讲清：Agent 在用户自己的机器上持续工作，用户从电脑或手机参与同一项任务，并从统一入口管理不同机器上的工作。

- 视觉与内容基准：[官网 V3 设计图](../../runweave-website-catalog-v3.png)。保留米白背景、橙色重点、细分隔线和产品目录布局；图片是设计参考，不是客户端现状或功能验收证据。
- 用户已选择方案四，首页主标题固定为“你不必一直在场，工作也能继续。”
- 用户提供的终端分享（快照 ID `14f2c517-7a09-4e56-96ea-6210b4033405`，第 184–212 行）最终收敛为 Astro + TypeScript + CSS、静态生成、首期首页。React、Markdown/MDX、CMS 不进入首期。签名分享链接会过期，执行不依赖再次访问该链接。
- 当前仓库基线 `f1639624`：没有官网包；`frontend/` 是产品 Web/Electron UI。`pnpm-workspace.yaml` 已包含 `packages/*`，根构建、lint、typecheck 使用递归脚本。
- 当前 CI 位于 `.github/workflows/ci.yml`，使用 Node 22、pnpm 10.6.2，已有 lint/typecheck，尚未单独验证官网构建。

这是官网计划，不是长任务执行系统的功能实施计划。官网不得把“可靠完成所有任务”“跨机器自动迁移”“所有环境能力完全一致”写成已交付能力。

## 2. 首期范围

交付中文首页 `/`、静态 404 页面、站点元信息、分享图、favicon、robots 与生产站点地图，以及可独立托管的静态构建产物。

首期用户行为：阅读产品价值，浏览工作方式与多机器说明，进入真实的使用指南、GitHub 和配套产品介绍。正文、导航与链接在禁用 JavaScript 时仍然可用。

不包含登录、支付、在线终端、Backend API、任务数据读取、CMS、博客、教程系统、多语言、产品详情页、网站统计和自动发布。配套产品独立介绍页留待有足够内容时再增加，不创建空页或只换产品名的薄内容页。

只实现官网；不改变 Backend、Electron、iOS、CLI 或现有产品路由，不把官网加入服务端 npm 包或桌面安装包。

## 4. 技术与资源方案

新增独立私有包 `packages/website/`，包名 `@runweave/website`。Astro 输出静态 HTML，TypeScript 管理少量配置与结构化内容，CSS 实现布局，不依赖产品前端组件、运行时 DTO 或 Backend。

Astro 默认支持预渲染；本项目显式采用静态产物，不增加服务端 adapter。参见 [Astro 渲染说明](https://docs.astro.build/en/guides/on-demand-rendering/)。

依赖版本在实施时选择与仓库 Node 22 的实际版本兼容的组合，并写入 lockfile；检查包的 engines，不直接引入会迫使全仓升级 Node 的版本。所需依赖限定为 Astro、TypeScript、`@astrojs/check`、`@astrojs/sitemap`；新增框架须有本期交互需求支撑。

页面文本直接写入 Astro 组件；短机器列表和产品目录放在本包 `src/data/home.ts`，不引入 CMS 或内容集合抽象。对外无新 API，只有构建时配置与静态文件。

### 4.1 资源处理

- 先盘点已授权的真实客户端截图；可用则采用经隐私检查的截图。缺少适用截图时，制作与设计稿一致的独立设备示意素材，并在临近图片的简短图注注明“界面示意”。
- 使用 image generation 工具编辑已有图片；不把整张 V3 页面当作首页背景，不通过图片承载标题、产品介绍或导航。
- 需要带透明背景的设备图时使用真正的透明素材，不用 CSS 隐藏整张截图中的正文。
- 资源放在 `src/assets/`，通过 Astro 图片能力输出适当尺寸和响应式格式。首屏主图不懒加载；下方图片懒加载，全部预留宽高或比例。
- 使用系统中文字体，Runweave 字标可用本地可用的 serif 字体或已有授权资产；首期不请求第三方字体服务。
- 参考图保持原文件不覆盖；本轮 V2/V3 图片目前未被 Git 跟踪，实施提交时应保留 V3 设计依据或将其复制归档，避免计划引用丢失，不擅自提交其他方向的图片。

### 4.2 构建配置合同

| 输入               | 规则                                                                          | 产物行为                                                                |
| ------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `WEBSITE_ENV`      | `preview` 或 `production`，默认 `preview`；其他值构建失败                     | 默认构建可用于 CI、本地评审，不能误当成可索引生产版本                   |
| `WEBSITE_SITE_URL` | 站点根地址，不含查询、凭据或片段；生产要求明确的 HTTPS 地址且不能为 localhost | 决定 canonical、绝对 OG 地址和 sitemap 域名；不向浏览器暴露无关环境变量 |
| 预览地址缺失       | 使用 `http://127.0.0.1:4321` 作为本地预览源                                   | 页面 `noindex`，robots 禁止抓取，不生成可提交的生产 sitemap             |
| 生产地址缺失或非法 | 清楚报错并停止生产构建                                                        | 不生成假域名 canonical；不复用上次产物进行发布                          |

部署根路径为 `/`，首期不支持子目录部署。正式域名与托管位置是部署前输入，不阻塞静态站点实现。预览和生产分别清空并重建输出目录，不能混用产物。

## 5. SEO 交付要求

- `/` 的初始 HTML 包含全部标题、正文和真实 `<a href>`；禁用 JS 后保留主要内容与导航。Google 能处理 JavaScript，但静态正文减少对执行阶段的依赖，不能承诺收录或排名。参见 [Google JavaScript SEO 说明](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。
- `<html lang="zh-CN">`；title 初稿为“Runweave｜让 Agent 持续工作，随时接续任务”；description 概括多机器执行与手机跟进，不堆砌关键词。
- 生产页面提供绝对 canonical、Open Graph 标题/描述/URL/分享图；404 使用 noindex，不把不存在的页面 canonical 到首页。
- 使用 `@astrojs/sitemap` 生成生产站点地图，只包含本期实际存在且可索引的 `/`，排除 404 与预览地址；robots 指向生成的实际 sitemap 路径。参见 [Astro sitemap 配置](https://docs.astro.build/en/guides/integrations-guide/sitemap/)。
- 不创建英文 URL、hreflang 或空产品详情页；待对应内容真正存在再增加。
- 托管层真实返回未知路由的 HTTP 404；禁止以 SPA fallback 对任意路径返回首页 200。
- 首期不添加评分、价格、用户数量或未经核验的结构化数据。搜索平台提交和收录验证属于上线后的独立动作。

## 8. 验收与验证方式

本期为静态展示网站，不涉及持久状态、认证或后台协议。本计划内的清单足以表达验收，不新增单元测试或独立 YAML 测试计划。以下均是实施阶段要求，本轮未执行官网构建或 UI 验收。

### 8.1 命令检查

新增脚本完成后，从仓库根执行：

```bash
pnpm --filter @runweave/website lint
pnpm --filter @runweave/website typecheck
pnpm --filter @runweave/website build
pnpm --filter @runweave/website preview --host 127.0.0.1 --port 4321
```

前三项须退出 0；构建目录包含首页与 404 HTML 和公开资源，预览默认 noindex。预览端口被占用时选空闲端口并记录，不停止其他会话的进程。

生产配置检查：`WEBSITE_ENV=production` 且未提供 `WEBSITE_SITE_URL` 时必须退出非 0，错误指出缺少真实站点地址；使用已确认地址后构建成功，所有绝对 URL 使用同一生产源，不能残留 localhost 或预览域名。

文件或 HTTP 检查须逐项证明：

- 初始 HTML 可找到主标题、三阶段正文、机器说明与产品名称，链接是静态 href。
- 本地资源路径存在；无指向未实现路由的站内链接。
- 生产 robots 与 sitemap 一致，sitemap 不含 404；预览页 meta robots 为 noindex。
- 正式静态托管中的未知路由返回 404；仅访问 `404.html` 成功不能替代未知路由检查。
- 文档变更运行 `pnpm docs:check`；检查 diff 只包含本计划范围。

### 8.2 浏览器验收

使用 `$toolkit:playwright-cli`，按当前终端身份解析并附着正确 Browser，在新标签页打开官网预览，保留用户现有标签。不需要启动完整产品栈；如果确需 Dev Session，必须遵循 `$toolkit:runweave-dev-session`。

| 场景                     | 预期                                                     | 失败判断                                        |
| ------------------------ | -------------------------------------------------------- | ----------------------------------------------- |
| 1440px 桌面与 390px 手机 | 叙事与 V3 一致，关键文案完整，设备图不压住正文           | 截图整页替代 HTML；文字裁切；图与任务内容不一致 |
| 320px 与 768px           | 无横向溢出，导航、三阶段、机器与产品区域正常重排         | 隐藏关键内容才能适配；按钮超出视口              |
