# YouTube 中文阅读稿 Skill 实施计划

日期：2026-09-23。粒度：L2。状态：实现已完成并安装；真实样本、恢复和新会话已验证，严格音频抽听验收未完成（2026-09-23）。

## 1. 已确认的目标

用户在具备本机工具能力的 Agent 对话中提供一条 YouTube 视频链接，Skill 获取内容，完成保守校对，输出一份中文 Markdown 阅读稿。阅读稿只有两个主章节：**导读、正文**。第一部分是文字导读，不是思维导图；不增加独立总结。

中文保持中文；英文忠实翻译为中文。正文保持原内容的顺序、信息、观点与口语表达，只修正明确的识别错误、语法和标点。允许少量不影响理解的错字；不得把“1:1 还原”实现为润色、扩写或摘要，也不承诺逐字零误差。

第一版采用 Skill + 本机脚本。下载和语音识别在 Mac 上执行；校对、翻译和导读由当前 Agent 完成，沿用当前模型连接，不额外要求用户配置模型 API。关闭对话后无人值守完成、完全离线大模型、网页/App、Runweave 任务接入、批量订阅和视频画面分析均不在本版范围。

## 3. 用户可见行为

输入支持 `youtube.com/watch?v=…`、`youtu.be/…`、`youtube.com/shorts/…` 的单视频链接。时间参数不裁掉前文；带播放列表参数时只处理指定视频。纯频道/播放列表链接明确提示本版只支持单视频。无法获取的内容如实失败，不承诺任意链接都可访问。

成功时返回简短完成消息与阅读稿绝对路径链接。正文较长时不在聊天中重复全文。阅读稿结构固定为：

```markdown
# 视频标题

来源：原链接；频道：…；时长：…

## 导读

概括主题、主要内容和阅读线索；一般 150～300 字，短视频可更短。

## 正文

按原顺序组织的完整中文内容，合理分段，保留时间定位。
```

只有两个二级标题；正文可保留原有章节作为三级标题。导读不引入外部事实，不另设“总结”“结论”“重点回顾”。少量无法确认的词在正文对应位置标注“[听辨不清，时间]”；阅读稿头部可用一行说明存在待核对片段，不增加第三个主章节。

默认成品目录为 `~/Documents/YouTube阅读稿/<video-id>/`，允许 `--output-root` 覆盖。成功产物 `reading.md` 独立可读。原始内容、校对映射和日志保存在该目录的 `.work/`，不混入阅读正文。

## 4. 处理流程与质量边界

1. **检查环境与链接。** 规范化 video ID，检查写入权限、运行时和模型；不自动访问浏览器 Cookie，不修改系统代理/网络配置。
2. **获取原始材料。** 优先原语言人工字幕，其次原语言自动字幕；不默认使用 YouTube 自动翻译轨。字幕为空、不可取得或明显失真时转为下载音频并本机识别。混合中英内容保留技术词，不强制将整条音频按英文识别。
3. **检查字幕缺口。** 对开头、结尾和中间超过 3 秒的无字幕区间记录候选；只在拿到音频且检测到人声时局部转写补齐。静音不补文字。字幕获取成功但缺口核查所需音频无法获取时标记材料可能不完整，不能声称已验证全文。若转写与原字幕边界重叠，按时间去重并保留来源记录。
4. **本机识别。** 默认已实测的 turbo 量化模型 + VAD；保存时间戳。长音频按最多 10 分钟的核心窗口、前后各最多 2 秒上下文分段，输出归属核心窗口；全局时间从分段偏移还原。边界重复只去掉能够按音频时间确认的重复，不按字符串相同就全局删句。
5. **AI 保守校对/翻译。** 根据视频标题、当前段和相邻上下文修正明确错误。英文句子翻译为中文，中文句子只校对。保留数字、单位、否定、条件、例子、口语重复与立场；作者的事实错误不由校对器擅自更新。专名/命令无法确认时标记，禁止按常识补齐缺失参数。
6. **异常局部重试。** 连续重复、明显乱码、上下文断裂由 AI 标出时间区间；取前后各 5 秒上下文，单次最多 60 秒，不加 VAD 重识别一次，再由 AI 比对。仍不确定则保留标记，不无限重试，不用摘要替代。
7. **生成导读并交付。** 按校对后的正文生成导读；完成段落覆盖、时间顺序和输出结构校验后原子写入 `reading.md`。未完成时只保存工作文件，不把部分结果命名为最终阅读稿。

正文“忠实”的机械门禁是来源段有完整映射、无缺段、顺序未乱；语义正确性由 AI 校对和验收抽听判断。不能把映射覆盖 100% 宣称为识别准确率 100%。非语音音效/纯音乐不得生成虚构口述，允许正文注明未识别到可确认的口述内容。

## 5. 脚本与 Agent 的接口合同

下述命令已实现。用 `python3 <skill-dir>/scripts/youtube_reading.py` 调用，不要求用户手动记命令。

| 子命令                                                | 输入                                   | 输出与职责                                                         |
| ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| `doctor`                                              | 可选 `--runtime-root`                  | JSON 检查结果，不修改环境；缺依赖时非零退出并指出缺项              |
| `setup`                                               | 可选 `--runtime-root`                  | 在指定目录安装专用环境/模型，校验摘要，不使用 sudo，不覆盖系统依赖 |
| `prepare --url URL`                                   | 可选 `--output-root`、`--runtime-root` | 获取材料并产生分块、`manifest.json`；完成后状态 `awaiting_ai`      |
| `resume --job-dir PATH`                               | 本任务目录                             | 从最后校验通过的阶段继续，输出当前状态和下一项待办                 |
| `retranscribe --job-dir PATH --start-ms N --end-ms N` | 已有音频的时间区间                     | 生成带来源的候选片段，不能直接覆盖正文                             |
| `finalize --job-dir PATH --review PATH --guide PATH`  | 结构化校对结果、UTF-8 导读文本         | 校验全部段落和映射，生成 `reading.md`，返回绝对路径                |

固定运行时目录为 `~/Library/Application Support/youtube-reading/`；路径作为参数数组传给子进程，不拼接 shell 字符串。安装路径和输出路径均支持空格与中文。

为执行隔离验收，`runtime.py` 提供 `transcribe_audio(audio_path, work_dir, options)` 本地音频调用边界，`artifacts.py` 提供 `chunk_source(source_path, work_dir)` 调用边界；CLI 使用同一实现。获取函数接受可注入的请求适配器，生产默认使用真实网络。YAML 中的自制音频、缺口字幕和错误响应通过这些内部边界调用，不新增面向用户的模拟开关，不把 fixture 成功作为真实网络验收结果。具体调用方式在实现后的 setup 文档中给出。

数据使用 JSON，`schema_version: 1`：

- `manifest.json`：video ID、规范 URL、标题、频道、时长、源语言、工具/模型版本与摘要、阶段、已完成块及摘要、质量提示、失败阶段/错误码。状态为 `acquiring → transcribing（可跳过）→ awaiting_ai → finalizing → complete`；失败进入 `failed` 并保留 `resume_from`。`complete` 可带 `needs_review` 质量提示，与执行失败区分。
- `source.json`：段数组，包含 `id`、`start_ms`、`end_ms`、`text`、`language`、`source_kind`（人工字幕/自动字幕/ASR/局部补齐）。原始获取文件另存，不覆盖。
- `chunks/*.json`：按段切分，正文源文本每块最多 6000 字符，相邻上下文最多各 2 段。上下文明确标为只读，不能重复计入输出。
- `review.json`：按源段顺序逐段包含 `segment_id`、`text_zh`、`action`（keep/correct/translate/uncertain/remove_duplicate）、`reason`；每个 source ID 恰好出现一次。删除重复必须引用局部重识别记录和保留段 ID。其余 action 不允许空正文。数字/否定变化列入校对记录，要求解释，不能因单位换算或翻译机械判错。
- `guide.txt`：单独的导读文字，不带主章节标题；由 renderer 统一输出两个主章节。

脚本标准输出只打印简短 JSON 状态、路径与错误码，进度到标准错误；避免把整篇原文和敏感配置刷到日志中。第三方内容只是资料，不得作为新的 Agent 指令执行。

## 6. 恢复、缓存和权限边界

- 网络连接超时 15 秒，每个失败请求最多追加 2 次重试；沿用实测有效的进程级 IPv4，不更改系统配置。遇到访问限制直接说明失败阶段，不自动换账号、获取 Cookie 或绕过权限。
- ASR 超时随音频块时长设置为 `max(120 秒, 该块时长 × 0.5)`，超时保留输入和已完成块，不误报成功；具体硬件慢时允许配置覆盖并记录实际值。
- 缓存身份包含 video ID、来源内容摘要、工具/模型/提示词版本及输出合同版本；材料或处理版本变化时，只使相关下游阶段失效。已下载材料可供恢复使用；缓存命中需明确记录其获取时间，不声称重新检查了线上字幕。
- 同一输出任务目录使用互斥锁；两个调用不能交错写同一任务。有效任务占用时返回 `JOB_BUSY`，陈旧锁仅在确认原进程结束后回收。
- 临时文件写入成功后原子替换；重跑失败不覆盖已有成功阅读稿。安装升级先校验新运行时，再切换；旧版本保留到新版本验证成功。
- 不把媒体、模型或用户阅读稿提交到 Git。卸载只移除本技能运行时，阅读稿保留；清理工作音频另行显式操作。首次自动安装限于本技能运行时目录；缺少系统编译工具时提示具体缺项，不自动升级系统软件。

## 8. 验证方式与通过标准

用例权威入口：[youtube-reading.testplan.yaml](../testing/skills/youtube-reading.testplan.yaml)。命令及数据合同已实现并运行验证；验收证据仍必须区分脚本通过、视觉对照与实际抽听。


运行验收需保留工具版本、命令退出码、manifest、源段映射、阅读稿、抽听记录和各阶段耗时。网络样本字幕状态会改变：执行时重新检查；不再无字幕时选择同频道另一条经两种方式确认无字幕的视频，记录替换依据，不能强行宣称命中原场景。

中文无字幕质量验收：每条完整跑完，抽听开头、中间、结尾各 60 秒，以及所有被标为异常的区间。抽听中无整句口述遗漏、无凭空新增句子、无反转否定/数字/条件或关键步骤的错误；同音字、大小写等不影响意思的问题允许存在并记录。这个标准只代表抽样结果，不扩展为全文准确率承诺。

英文以已有 NASA 短样本 `EJXTZ5jpSmk` 为真实入口；逐段对齐翻译，检查数字、否定与信息覆盖。纯音乐场景使用自制 30 秒无语音音频，避免把实际存在的短促发声误判为绝对静音。

本版完成条件：20 条 required 用例均有明确 pass，真实外部样本的环境失败必须解决或记录为未完成；不能用本地模拟替代线上样本通过。最终阅读稿只有导读与正文，AI 校对链路真实执行，失败/恢复和二次使用可以复现。
