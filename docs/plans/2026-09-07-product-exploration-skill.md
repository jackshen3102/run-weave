# 产品探索 Skill：轻量接入计划

状态：第一步完成，结构/格式/文档检查通过；用户已授权 PR 交付，本机插件随提交钩子同步。第二步的新线程加载验证与第三步真实探索尚未执行。粒度：L1。日期：2026-09-07。

## 目标与已确认边界

让当前 Coding Agent 在用户明确要求时，围绕一个功能或用户目标探索真实产品，发现问题、收集证据并提出建议。目标不是建立回归测试资产，也不是要求每次代码修改都验收。

- 仅明确调用或明确要求产品体检时启动；不随修改、提交、PR 自动启动。
- 用户给出功能或用户目标，Agent 自主探索相关路径和异常边界，不扩展到无关模块。
- 默认探索预算 30 分钟，不含环境准备。可以提前结束，不为用满时间或凑问题数量继续操作。
- 可以使用真实环境和真实数据；真实数据默认只读。写入使用本轮临时数据；修改真实数据、提交内容或向外发送消息需单独授权。
- 只发现、取证、报告；不自动修改产品实现。后续修复由用户另行确认。
- 不新增持久化测试代码、测试框架、CI 门禁或自动修复流程；不要求用户准备 YAML。
- 报告区分已确认缺陷、待确认疑点、体验建议；宁可少报，不编造问题。

## 当前基础与路线选择

- `plugins/toolkit/skills/` 是已有 Skill 规范源，插件已声明从该目录加载能力。
- `playwright-cli` 已提供真实页面操作、快照、截图和诊断能力，并规定正确的 Profile、Session 与 CDP 边界。
- `runweave-dev-session` 已管理源码运行环境及生命周期，不重新实现服务启动和身份解析。
- `run-test-cases` 用于既有 YAML 合同的逐条验收、默认首错即停；不把它改造成探索工具，也不把探索任务强行转为 YAML。
- `reproduce-before-fix/agents/openai.yaml` 已使用禁止隐式调用的配置模式，可复用。

因此先新增单一 `product-exploration` Skill。借鉴 Playwright Test Agents 的探索、观察和诊断方法，不安装官方 Planner / Generator / Healer 三角色，不引入新的 Test Runner MCP。以后是否需要其中某项能力，由实际使用中暴露的缺口决定。

## 使用合同

示例意图：`使用 $toolkit:product-exploration，检查文件搜索体验，预算 30 分钟。`

必需输入只有功能或用户目标。环境和入口优先从当前任务上下文、项目配置和已有工具解析；不能确认目标或资源归属时才问用户，不要求填写表格。

执行过程：

1. 简要复述范围、入口、数据权限和预算；只读查看必要代码或文档以理解预期，不做全仓扫描。
2. 复用可确认身份的运行环境；需要未提交源码环境时遵循 Dev Session 规则，不能混用旧端口或用户无关页面。
3. 页面可操作后记录探索起止时间和截止时间；环境准备时间单独记录。操作之间检查剩余预算，为报告与清理预留时间，不承诺 Skill 能强制中断正在运行的工具。
4. 先走用户目标主路径，再根据观察选择相关的中断、返回、空数据、边界输入、连续操作等路径。这是探索启发，不是固定测试清单，也不要求每项必跑。
5. 发现异常后最小化复现并复核一次；避免重复制造有风险的副作用。不可安全复核、结果不稳定或预期不明确时列为待确认。
6. 某条路径被阻塞时可以继续独立且在范围内的路径；不要为了探索而修产品或擅自放宽权限。环境不可用则如实报告，不把静态阅读当作运行证据。
7. 到期、范围内无有价值的新路径，或无法安全继续时结束。报告未覆盖范围，不宣称完整验收或“没有 bug”。

预算是本轮探索上限，不是必须消耗的时长；用户可以另行追加。30 分钟到期后不再展开新分支，必要清理和报告仍应完成。

## 输出与数据安全

交付简短中文结论和一份本地探索报告；需要时附最小截图或诊断片段。建议保存至 `artifacts/product-exploration/<本轮唯一标识>/`，不进入正式测试目录。

报告包含：

- 目标、实际环境、探索耗时和数据权限；已覆盖与未覆盖范围。
- 已确认缺陷：用户影响、最短复现步骤、预期及依据、实际结果、证据、复核情况与建议。
- 待确认疑点：观察到什么、为何尚不能下结论、还缺什么证据。
- 体验建议：如何妨碍用户完成目标，区别于功能缺陷和个人审美偏好。
- 清理结果、仍需用户决定的事项。未发现问题时如实写明，不凑数量。

临时自动化代码只服务当前探索；不生成 `*.spec.*` / `*.test.*`、不恢复 `frontend/tests`，不沉淀成需要维护的测试资产。报告和必要证据可以留存；临时执行文件与测试资源收尾清理。

真实数据不默认进入报告附件；优先裁剪和脱敏，不输出凭证、Cookie、Token、完整敏感响应或无关个人信息。能读取不代表可以导出或发送。不能安全脱敏的证据只描述现象，标注证据限制。

临时数据必须能证明归属本轮，清理仅针对这些资源。不得为“隔离”而清空用户 Cookie、重置账号或删除真实目录。仅停止本轮创建的 Session，已有用户环境保持原状。

## 分步实施

### 第一步：固化最小 Skill

拟新增：

- `plugins/toolkit/skills/product-exploration/SKILL.md`：触发边界、探索策略、预算、授权规则、输出与清理要求。
- `plugins/toolkit/skills/product-exploration/agents/openai.yaml`：显示名称、调用提示、`allow_implicit_invocation: false`。

拟修改：`plugins/toolkit/README.md`，只补充能力入口。

第一版不增加 helper、自动编排、后端接口、产品 UI、定时任务或 Hook。若实际试用证明仅靠现有工具无法满足某条约束，再带着证据讨论是否补机制，不预先搭框架。

### 第二步：验证规则与加载

- 实施前读取 `skill-creator` 完整指令，使用现有结构校验工具验证新 Skill，不新增测试文件。
- 运行 `quick_validate.py <新 Skill 路径>`、`pnpm docs:check`、`git diff --check`；要求成功，无新无效链接或格式问题。
- 人工审阅触发描述和规则：普通改代码请求不应触发；没有测试代码产出或自动修复要求；写真实数据前必须申请。
- 本地发布沿用 `plugins/toolkit/README.md` 的 Toolkit 同步机制，不手改缓存或使用软链接。`pnpm toolkit:sync` 会同步并重装本机插件，不把它当作只读检查。
- 在新线程确认新 Skill 可见；磁盘文件存在、结构校验通过不等于当前会话已加载。新线程不可用时记录加载验证尚未完成，不用手动读取文件冒充原生调用成功。

### 第三步：做一轮真正的探索试用

使用新 Skill，选择一个明确的 Runweave 用户目标，按 30 分钟默认预算实际探索。优先选已有入口、可安全创建临时数据且包含真实交互的功能；不承诺一定发现新问题。

本轮一次性验收关注：正确绑定环境、自主选择相关路径、真实操作与证据、预算记录、三类结论分离、读写边界、资源清理。验证无产品源码被自动修改，无持久化测试文件、YAML 或 CI 改动。

依据试用结果，只修正 Skill 中产生歧义或额外成本的规则。若规则不能被可靠遵守，报告实际缺口，不用“智能 Agent 会自己处理”作保证。

## 完成标准与非目标

完成需同时满足：新 Skill 结构校验通过、在新线程可显式调用、一次真实探索报告可复核、未产生测试代码或自动修复副作用、测试资源已清理。静态检查与真实使用结果分别报告。

本次不做：官方三 Agent 全量接入、测试生成/自愈、全产品扫描、单元测试、自动提交 issue/PR、自动发消息、自动产品修复或产品内入口。未经另行要求，不提交、推送或合并代码。

兼容性：既有 Skills、YAML 验收、Playwright 配置及测试策略保持不变；无 API 或数据迁移。Skill 约束不是安全沙箱，不声称能越过或代替运行环境权限控制。

回退：停用/移除本次新 Skill 及其入口并按既有机制更新插件；不影响既有产品与测试流程。项目标签布局修复是独立改动，不属于本 Skill 的回退范围。

确认后按第一步开始；每一步交付后再推进下一步。本计划是实施计划，不是 Markdown 测试案例；按用户已确认的轻量边界，不配套新增 YAML 测试资产。完成后依仓库文档治理移除过程计划，将仍有效的使用合同留在 Skill 中。
