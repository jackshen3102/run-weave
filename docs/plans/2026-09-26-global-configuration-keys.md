## 范围与计数

- 迁移前审计基线为 332 个具名环境键，包含直接访问、动态 allowlist、输出上下文、部署模板和历史 hook；分类为 持久配置 101、系统环境 33、构建部署 32、测试参数 35、运行上下文 107、历史入口 7、外部工具 5、部署管理 12。它们不是 332 个用户设置。
- 143 个已注册 YAML 字段路径模式（含 4 项必须保留的迁移/版本元数据），逐项列出类型、用途与来源；同义环境变量合并，动态 map/array 用占位表示。
- 迁移前基线有 109 条非环境字段记录、28 个设备存储键/键族；截至 #598 新增 1 个 iOS 设备键，当前分别为 110 条与 29 个。它们与 YAML 字段存在重叠，不能把数字相加。

范围为 Git 跟踪的 Runweave 源码、scripts、deploy、原生客户端与历史通知 hook。排除第三方 Vendor/node*modules、业务数据库中的记录字段、任意用户内容、私有忽略文件和第三方应用自己的设置全集。动态生成的键按规则枚举，不把无限的项目名/账户名当成已逐个找到的有限 key。源码全量盘点不等于读取此电脑全部配置；本轮没有导出本机密码、Token 或 Keychain。模板中 LIVE*\* 无当前消费者证据，明确归验证参数，不能宣称已生效。

最初的 285/773 是直接访问扫描基线，本轮补上动态 allowlist、部署与历史 hook 后以本清单及 CSV 为准。字段合同已落盘，实际消费者及默认值仍在逐项回归；代码已注册不等于全部生命周期验收通过。当前新增的进程上下文读取按 scripts/quality/configuration-accesses.json 逐访问点分类，门禁不允许新增未登记读取。

基线后的两个具名环境键属于 Web 构建参数，见 [Clarity 配置合同](../../frontend/docs/clarity-autocapture.md)：

| key                       | 归属           | 默认与生效                           |
| ------------------------- | -------------- | ------------------------------------ |
| `VITE_CLARITY_ENABLED`    | frontend build | 未配置时关闭；重新构建后对新页面生效 |
| `VITE_CLARITY_PROJECT_ID` | frontend build | 无默认值；仅构建启用的普通 Web 读取  |

## 动态规则与边界

- `RUNWEAVE_SERVICE_<SERVICE_NAME>_URL`：项目服务名转大写并把连字符替换为下划线；属于运行上下文。来源：`backend/src/terminal/workspace-service/environment.ts:9`。
- `npm_*`：第三方 package runner 环境，过滤而非产品配置。来源：`backend/src/terminal/workspace-service/environment.ts:27`。
- `terminal.browser.headerRules.<profileId>`：profile-1/profile-2/profile-3 三个 profile 的请求头规则。来源：`frontend/src/components/terminal/browser/header/use-headers.ts:10`。
- `domainVersions.<domain>`：拟新增分域版本元数据，不是现有业务 key。来源：`docs/plans/2026-09-26-global-configuration.md`。

- 现有终端草稿、快捷回复、Browser tab/session、预览 workspace、通知订阅、已读标记、任务定义/历史属于内容或状态，保留既有数据模型和实例归属，不为每个数据库列新增设置 key。
- 配置表中的外部随记 production/development profile 是服务连接选择，不新增 Runweave Beta 运行身份；隔离由 Stable/Dev Session 的实例根承担。
- 本次选择 YAML 只修改新全局配置合同；旧配置 JSON 经单向迁移读取，项目 runweave.json、数据库和平台 Keychain 格式保持原合同。
