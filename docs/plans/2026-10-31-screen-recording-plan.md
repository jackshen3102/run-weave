## 1. 目标与使用范围

为个人的一台 Mac 提供全天屏幕活动记录，帮助用户在近期回看原始画面，并让外部工具在需要时读取材料进行分析。

保留截图记录的核心能力，分期增加使用能力，不能通过删掉核心采集链路来降低一期成本。基础策略整体参考 Dayflow，经源码核实后使用，不逐项重新发明参数。

已确认的边界：

- 面向个人使用，暂不考虑账号、付费、团队管理和对外分发体系。
- 首期采集来源是一台 Mac，不做多台设备的记录合并。
- 第一期只交付采集与可靠存储，包括必要的权限、启停、状态和配置控制；Mac 与手机的记录浏览均放到第二期。
- 采集功能独立，不强依赖 Runweave；参考 RemoteDesk 的独立功能组织方式。
- 本工具负责采集、存储和展示，不内置模型调用，也不等待分析完成才继续采集。
- Mac 提供采集与本地查看；手机是重要使用端，手机界面必须原生，入口放在 Runweave iOS。
- 不使用手机网页作为展示方案，不另建一个独立手机 App。
- 手机复用 Runweave 当前连接、接口鉴权和令牌刷新，通过 Runweave Backend 的受保护接口访问本机记录；不增加 ScreenJournal 独立登录或配对。Mac 采集仍可脱离 Runweave 运行。
- 第二期手机端先在 iOS 模拟器中实现和验证；模拟器需要读取本机 Mac 服务的真实采集记录，不能只用静态样本代替完整链路。第一期不修改手机界面，不以模拟器验收作为采集交付条件。
- 只支持在线查看：Mac 服务不可达或手机离线时无法查看，不提供离线浏览能力，不建设离线同步副本。
- 外部分析结果可以写回，并关联原始记录；这是后续迭代能力。
- 随记只保存多来源整理后的最终记录，不承担截图浏览、原始材料或中间分析展示。
- 写入随记、自动还是人工确认、每日总结调度均不属于一期，本轮不继续细化这些决策。

## 2. 两类数据及保存边界

| 数据         | 用途与展示                                                         | 生命周期                            |
| ------------ | ------------------------------------------------------------------ | ----------------------------------- |
| 原始屏幕记录 | Mac 和 Runweave iOS 查看截图、画面片段和近期时间线；供外部分析读取 | 默认 7 天，可调整，并有磁盘容量上限 |
| 最终工作记录 | 多来源合并后的每日总结等最终内容，长期归档于随记                   | 持久保存，不依赖原始截图持续存在    |

近期记录达到时间或容量上限时，清理最早的原始记录。7 天是时间保留上限，不承诺容量不足时仍能保存完整 7 天。容量默认值需根据真实编码占用确定。允许为在线展示使用有界临时缓存，但不能依靠缓存提供离线浏览；断线后明确显示不可用，缓存不能延长原始记录的可访问期限。

本工具不承诺任意历史日期的截图均可回看。过期原始画面应明确显示已过期，不能把资源不存在表示成暂时加载失败。未来若保留手机缓存或导出副本，需要分别明确它们的清理与过期规则。

外部分析失败或尚未整理时是否存在额外保留机制，尚未单独确认；当前不引入自动延长保留的承诺，也不让一期清理依赖随记写入流程。

## 4. 技术方向与当前仓库依据

建议采用独立 Swift 采集和存储核心，Mac 使用 SwiftUI；手机在 Runweave iOS 内实现原生浏览。手机原生要求及入口已确认；具体 Mac 工程、持久化库、接口传输方式仍需技术设计收敛。

已有依据：

- [RemoteDesk 构建配置](../../packages/remote-desktop-host/project.yml)是独立 macOS 原生 App，依赖本地 Swift 协议包。
- [应用入口](../../packages/remote-desktop-host/Sources/RunweaveRemoteHost/RemoteHostApp.swift)与[采集实现](../../packages/remote-desktop-host/Sources/RunweaveRemoteHost/DesktopCapture.swift)可供研究原生工程组织和系统能力接入。
- RemoteDesk 当前是实时远控场景；它的高帧率视频传输、会话生命周期，以及关闭最后窗口即退出的行为，不能直接作为全天记录工具的合同。
- 新功能不应挂在 RemoteDesk 远控会话是否开启之上，也不修改其现有身份、授权或媒体协议来隐式承载历史截图。

建议的职责分层：

1. 采集层：权限、定时截图、显示器跟踪、应用排除和系统状态响应。
2. 本地记录层：媒体编码、时间索引、规则状态、保存期限、容量管理与恢复。
3. 数据访问层：按时间分页查询、获取预览和原始画面；后续增加外部结果写回。
4. 展示层：Mac 本地浏览、Runweave iOS 原生浏览，均不拥有采集生命周期。
5. 外部消费层：分析程序使用接口读写数据；随记归档流程以后独立设计。

一期实现采集层和本地记录层，提供必要的采集控制及诊断。查询服务、远程访问与两端浏览属于二期；结果写回属于后续阶段，不作为一期运行条件。

一期需要稳定记录标识、实际采集时间与设备来源，避免后续查看或分析结果只能关联易变文件路径。应能使用本地诊断工具核验索引及解码抽样画面，不为验证采集额外实现完整浏览产品。分析结果后续独立版本化，不能覆盖原始采集事实。具体数据结构与接口字段在设计收敛时定义。

### 第二期的回放行为与迭代顺序

两端采用同一交互：选择日期与时间段 → 打开回放 → 播放快速回顾，或暂停并拖动定位某张画面。Mac 保留日期、记录列表、回放区三栏；iOS 在 Runweave 内进入原生回放详情。

- 大画面与底部胶片带属于同一段记录。胶片带只抽取代表帧帮助定位，不是全部截图列表；拖动任意位置可以定位该时刻对应的可用采样，不局限于缩略图中的几帧。
- 打开详情先显示首个可用画面，处于暂停状态；点击播放开始回放。速度为 20×、40×、60×，首次默认 20×，后续记住用户选择。示例图展示暂停在 09:42:10 的状态。
- 时间轴与当前时间使用真实采集时间，倍速表示每秒推进多少秒的真实记录时间。MP4 中第 N 帧的 PTS 仅用于解码定位，不能作为实际时间。系统时钟回拨的记录按会话序号区分，回放范围在回拨处断开，不能生成负时长。
- 拖动时暂停回放、更新当前画面和时间；松手后恢复拖动前的播放状态。支持上一帧、下一帧，手动逐帧后保持暂停；到选定范围末尾停止，重新播放从头开始，不自动跳到下一段。
- 状态事件标识的暂停、锁屏或采集失败区间显示缺口，隐私区间显示锁形占位。进入这些区间时不沿用上一张画面伪装连续记录，也不尝试恢复被排除的内容。正常采样间隔内保持最近一帧，并展示该帧实际采集时间。
- 只读取 ready 段；writing 段显示“最近记录整理中”。打开的回放范围固定，新提交内容通过刷新列表进入，避免正在拖动的时间轴突然伸长。跨物理分段按时间索引衔接，不改变一期存储格式。
- 手机检测到断线后暂停并隐藏图像与缩略图，重连后重新校验范围有效性并保持暂停。按二期实施计划每 2 秒核验，超过 5 秒无有效确认则不可查看；不宣称瞬时感知物理断网。连接切换或登出取消旧请求、清空旧内容；过期或清理后的帧按有效性合同失效。

一期的 `ScreenJournalInspect extract` 要求共享锁且不能与 writer 同时运行，因此 2.1 是回放实现前的必要工作。当前包规则仅覆盖一期采集；二期实施时需同步更新该包就近规则以纳入本地只读与 Mac 查看职责，iOS 界面仍留在 Runweave iOS。保持现有 SQLite 与媒体兼容，不为回放重编码历史记录。未达到上述能力前不能将静态图片或解码样本声明为完整回放已完成。

## 6. 后续细化与验证重点

二期手机读取条件已确认：只要求 Mac 在线可达时查看，不需要 Mac 休眠或离线时继续查看。二期先通过 iOS 模拟器连接本机记录服务验证原生页面和真实数据链路；局域网真机、外网访问与后台网络条件不属于模拟器验证结论。

后续技术核查按依赖顺序推进：

1. 固定 Dayflow 参考提交，列出保留、修改、排除的行为，核查源代码复用与许可。
2. 确定独立工程及数据目录，明确应用窗口关闭、退出、登录启动的行为。
3. 核查媒体编码、随机取帧和索引；实测全天 CPU、内存、磁盘增长，确定资源预算。
4. 定义查询、帧访问与未来结果写回合同；手机连接与鉴权已确定复用 Runweave，继续细化本地只读适配和媒体路由。
5. 明确自动清理、正在写入分段、正在读取资源及异常退出的协调规则。
6. 补齐精确文件范围、验证入口及逐期验收要求，形成可以执行的实施计划。

一期必须覆盖的验收方向：

- 关闭 Runweave 不应中断已启用的采集；关闭采集控制窗口与明确退出采集应用的行为要区分，退出时正常结束写入。
- 锁屏、休眠、唤醒、权限撤销与显示器变化后，状态与实际采集一致。
- 排除应用的真实内容不进入媒体文件；存储的状态和时间信息能解释对应缺口或占位。
- 原始时间以实际采集时间为准，不能以压缩视频播放时长推算工作时长。
- 达到保留期限或容量上限后按规则清理，索引与媒体保持一致，不误删正在提交的记录。
- 中断写入后重启，已提交记录仍可读取；失败不能静默显示为正常记录。
- 用本地诊断工具查询时间索引并解码抽样截图，确认压缩存储可读；此项不要求产品化浏览界面。
