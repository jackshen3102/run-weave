# ADR-0001：状态拥有者判断，客户端统一合并

- 状态：已接受
- 日期：2026-09-06

## 背景

运行状态面板需要用同一种结构展示本机节点与当前远程连接。当前运行依赖分布在多个相互独立的所有者中：Electron 拥有本机桌面进程和端口，Backend 拥有服务端运行时，Frontend 拥有客户端连接，App Server 与飞书 Bridge 又有独立生命周期。

任何单一运行时都无法准确观察整个应用。Backend 看不到 Frontend 是否真正连上 WebSocket，也不拥有 Electron 的 CDP Proxy、Whistle 或 Companion；Electron 则无法观察远程节点和移动客户端。让一个运行时重新探测其他所有者会引入反向依赖并产生假健康。

## 决定

Runweave 运行状态采用“拥有者判断、统一协议、客户端合并”的模型。

- 每个运行时只判断自己拥有的运行依赖，包括配置、所有权、进程、端点、连接和周期任务新鲜度。
- 跨运行时状态项使用共享合同表达相同的身份、状态与时间语义。
- 客户端把多个状态来源的标准化结果合并成运行状态快照；合并过程不重新解释健康规则。
- Frontend 自己观察到的连接和轮询状态也是标准化状态来源。
- 服务端状态可以经 Backend 受控转发，以支持远程和移动客户端，但 Backend 不因此取得其他运行时的状态判断权。
- 某个来源整体不可达时，由其消费者生成该来源不可用的状态，并可以保留最后已知快照。
- 本决定不规定状态传输方式、刷新频率、具体状态项清单或面板布局。

## 备选方案

### 由 Backend 判断全部状态

不采用。Backend 无法直接观察 Frontend 和 Electron 的真实状态，代为探测会复制其他运行时的生命周期语义。

### 由 Frontend 直接探测所有组件

不采用。浏览器与移动端无法安全访问主机进程、状态文件和内部端口，也会把健康规则复制到不同客户端。

### 由 Electron 汇总

不采用。它无法覆盖 Web、移动端和远程节点。

### 由 App Server 或新增监控进程汇总

当前不采用。App Server 允许缺失和降级，新增常驻监控进程则扩大了生命周期与部署面，都不符合操作型状态面板的目标。

## 后果

- 状态判断留在最了解生命周期与重试策略的所有者中，避免用端口存活猜测业务状态。
- 本机、远程、Web 与移动客户端能够共享相同的状态项语义和面板结构。
- 需要定义稳定的共享状态合同，并为进程外状态来源提供受控的报告或转发方式。
- 客户端需要执行确定性的合并与去重，但不负责组件级健康判断。
- Backend、Electron 或其他来源完全不可达时，仍需由外层消费者显式生成来源级异常。
