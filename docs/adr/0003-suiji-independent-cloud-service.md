# ADR-0003：随记服务独立部署到云服务器

- 状态：已接受（设计决定，尚未实现）
- 日期：2026-09-07

## 背景

随记需要支持手机随时记录和查询。用户已确认：手机有网络时，即使 Mac 关机或 Runweave 本机 Backend 离线，随记仍需可用；随记服务将独立部署到云服务器。

当前 `backend/` 是 Runweave 本机控制面，`app-server/` 是独立的本机 Agent 事件与状态服务，职责见各自 `AGENTS.md`。现有 Swift 客户端通过选中的 Backend 连接工作，其登录和请求生命周期见 `packages/app-ios/Sources/RunweaveIOS/State/AppSession.swift`。这些现状不能被当作已经存在的随记云服务。

本轮新增独立的原生 Swift 应用，未来可能与 `app-ios` 合并，因此需要协调客户端架构；这不要求随记业务依附本机终端运行时。

用户进一步确认：后续需要 Web 界面方便电脑录入，并接入现有 Runweave 桌面端，前后端保持分离。

## 决定

随记服务独立部署在云服务器上，客户端的记录保存、查询和修改直接依赖该服务，不依赖用户的 Mac、桌面客户端或本机 Backend 在线。

与现有 iOS 应用保持架构一致，优先体现在客户端分层、协议边界和生命周期管理上；不能据此把本机节点连接作为随记使用前提。

Swift App 与后续 Web 界面通过独立 API 使用同一随记服务。Runweave 桌面端承载 Web 界面，但其本机 Backend 不成为随记业务的必经服务；记录的归属也不跟随桌面端当前选择的终端节点变化。

本决定只确定客户端、部署与运行依赖边界，不确定云服务的目录、认证方案或 Swift 共享包拆分。

## 备选方案

### 将随记业务挂在用户 Mac 的 Backend 上

可以较少改动地沿用节点连接和认证，但 Mac 休眠、关机或不可达时，手机无法完成记录操作，不满足已确认的使用场景。

### 在云端部署整套 Runweave 节点来承载随记

可以利用现有节点 API，但随记会承担无关的终端控制面及其生命周期依赖。当前没有要求随记云服务器运行终端或 Agent 节点，因此不以该方式承载随记服务。

## 后果

- 用户 Mac 离线不再影响云端记录操作；云服务不可达时保留内容的语义见[随记领域词汇](../../CONTEXT.md)。
- 需要为随记建立独立的服务部署、身份接入与数据持久化能力，不能直接假定本机节点账号就是云端用户身份。
- 后续在客户端层整合随记入口时，需独立管理云服务地址与身份，保留其独立于终端节点的运行边界。
- 本决定不引入离线自动同步；草稿与已确认保存记录的区别由领域词汇定义。
