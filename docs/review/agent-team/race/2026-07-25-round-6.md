## Resolved Findings

### P1（已解决）：Worker Diff 首次打开复用陈旧 Changes 缓存

- 位置：`frontend/src/components/terminal/terminal-race-panel.tsx:284-300`、`frontend/src/components/terminal/use-terminal-preview-panel-data.ts:97-103,234-275`、`frontend/src/features/terminal/preview/store.ts:290-310`
- 修复核对：`openWorkerDiff()` 在切换到目标 Worker 后，使用 `scope + worker.worktreeId` 精确清除 Changes query，再打开该 project 的 Changes 视图并递增 project-scoped refresh revision。
- 数据所有权：Preview hook 只订阅当前 `activeProject.projectId` 的 revision；消费事件时通过同一 `terminalQueryKeys.previewChanges(scope, projectId)` 和既有真实 Git API 重新加载，并按新 payload 更新选中文件。
- 时序核对：静态契约结果为 `focusBeforeRemove=true`、`removeBeforeOpen=true`、`openBeforeRequest=true`、`exactProjectKey=true`、`projectScopedRevision=true`、`changesModeConsumer=true`、`samePreviewQueryKey=true`。
- RACE-009 影响：目标 Worker 的首次 Diff 不再依赖手动 Refresh；兄弟 Worker 的查询、选择与内容仍由各自 projectId 隔离。
