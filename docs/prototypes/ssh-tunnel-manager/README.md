# 端口与隧道管理原型

2026-09-25 设计评审原型，用户已认可主要交互，新增持久化和环境隔离要求记录在配套计划；尚未按最终实现冻结。不代表当前产品能力；本目录作为历史设计产物保留。仅修改独立原型，不修改生产代码。

## 原型简报

- 目标：SSH 与端口转发脱离 Runweave 连接记录，使用独立配置与生命周期。
- 用户：在桌面使用远端开发服务、或让远端 Agent 控制本机 Browser 的开发者。
- 入口：工作区右上角「更多操作 → 端口与隧道」，本机级右侧抽屉。
- 动作：添加/编辑/移除 SSH 主机，连接/断开，添加/编辑/删除/启停同端口转发，配置 Browser 通道。
- 主流程：打开抽屉 → 配置 SSH 主机 → 连接 → 添加端口或启用 Browser → 关闭抽屉继续工作。
- 关键状态：空列表、未连接、连接中、已连接、端口停用/冲突、浏览器通道关闭、SSH 失败。
- 非目标：多后端项目并排、通用 SSH 终端、任意反向端口配置、SOCKS 代理、Whistle 规则编辑、远端部署、Agent 安装。

## 使用

优先从 Runweave 的 Open Prototypes 中查看此目录。独立预览无需构建：

```bash
python3 -m http.server 6188 --bind 127.0.0.1 --directory docs/prototypes/ssh-tunnel-manager
```

打开 `http://127.0.0.1:6188/`，从右上角「···」进入。

直接评审抽屉：`http://127.0.0.1:6188/?panel=open`。

## 采用的交互与取舍

- 使用一个抽屉，不重复建设全屏页面；小屏时抽屉占满宽度。
- 按 SSH 主机分组，不使用当前连接作为配置作用域，也不自动新增 Runweave 连接。
- 普通转发与 Browser 回连分别启停、分别显示状态。连接 SSH 不等于两个子能力都可用。
- 每个开发转发只填一个端口，本机 `127.0.0.1:P → 远端 127.0.0.1:P`。冲突直接失败，用户调整，不自动换端口。
- Browser 反向通道由产品管理，用户只设置远端后端端口和允许使用的 Browser，不暴露票据、临时网关端口等实现细节。
- 配置在抽屉内进入编辑页，用返回按钮返回列表，不叠加第二层抽屉。
- 关闭抽屉和切换当前连接不影响通道；断开主机停用其实际通道但保留配置。
- 修改 SSH 目标后断开原通道，等待用户连接新目标；删除主机前明确说明停用影响。
- 运行故障可在面板外通知一次，并提供查看入口；计划产品实现需接入既有通知机制，不在更多按钮增加常驻数字或红点。

## 场景与验证

- 默认：从更多打开，关闭后再打开，列表状态保留。
- `?panel=open&scenario=empty`：空列表，添加 SSH 主机。
- `?panel=open&scenario=conflict`：3001 被占用，显示错误；原型「重试」固定恢复成功，不代表真实端口释放。
- `?panel=open&scenario=ssh-error`：身份验证失败，重新连接固定成功。
- `?scenario=drop`：8 秒后 SSH 断开，在面板外提醒，点击查看定位管理面板。原型不会执行真正的自动重连。
- 添加端口、同一主机重复端口拦截、编辑 Browser、断开后子通道等待、切换连接后状态保留。
- `prototype-preview.png` 为通过浏览器打开和检查后保存的实际原型截图。

## 实现边界与待解决事项

现有代码是 SSH 配置绑定 connectionId；不能通过搬动界面实现解耦。生产实现需独立 tunnelHostId、持久化与运行时归属，替换依赖 connectionId 的网关绑定，并处理既有配置迁移。这不等于保留两套长期兼容路径。

Browser 回连依旧依赖真实 Runweave 后端、认证与终端身份。原型样例假定已授权，认证首次建立、失效与撤销尚未绘制；后续必须复用既有认证能力，不能强制创建一个可见连接记录，也不能移除授权校验。没有后端的主机仍可使用普通端口转发。

需要避免后端目前「选择最后注册的 Browser 绑定」造成多个桌面争用；独立管理时应明确终端与桌面通道的归属。多个主机争用同一 Browser Profile 的限制保持原有语义，不能由此原型推导允许越过已有占用边界。

## 评审补充：配置归属

用户确认配置为桌面用户级文件，不属于当前连接、项目或 Backend 数据库。正式版沿用桌面 userData，Dev Session 使用独立目录；SSH 与 Browser 代理都要持久化且环境隔离。手机将来只读取所连接 Backend 的同机桌面配置，不做跨机器汇总。本轮不修改原型模拟持久化来冒充产品能力。
