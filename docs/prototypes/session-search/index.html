已有能力抽取复用拟新增

一个正文来源，多种格式适配。 原生会话记录 → 解析与分块 → 全文索引 → 搜索。Activity、App Server 事件、Work History、日报和经验库都不作为正文输入；文件监听与扫描只负责发现原文件变化。SQLite 与解析缓存是派生数据，不再回流成为另一套来源。其他机器的会话由其 Backend 提供，第一阶段不做跨机器聚合。

PROPOSED BEHAVIOR

查询行为
完成后的水位
    增量解析 ≠ 只读取新增字节

    现有日报读取器在发现追加时，会先重读已处理前缀以校验哈希，再从检查点解析新行。第一阶段延续这条保守路径；要降低旧字节读取量，需要另有可靠的来源版本或不可变分段合同，不能仅凭文件变大就认定历史没变。

    • 不把 assistant 自述当成操作成功。
    • 默认不把历史正文直接升级成经验。
    PROJECT EXPERIENCE / 已有

    “下次碰到这个问题，应怎样处理？”

    返回适用条件、反例、处理步骤与验证方式；沿用现有版本、证据、有效期与反馈机制。

    • 保留现有学习与审查流程。
    • 只有来源明确关联时，才提供相互跳转。
    • 检索命中、采用回执和实际收益分别统计。

    交接单不进入第一阶段。未来若需要，由 Agent 读取已核实上下文后整理目标、进度与待办，并为关键动作带回执；不把正则拼接生成的文本作为执行事实。

    职责技术 / 落点选择依据
    读取基础能力TypeScript / Node.js

    packages/agent-history-node/（拟新增）

    索引服务Worker Threads + better-sqlite3

    backend/src/session-search/（拟新增）

    		复用已有数据库 Worker 模式。单写入队列、读写预算和取消/恢复合同由 Backend owner 管理。
    查询与排序SQLite FTS5 trigram + BM25

    独立可重建索引库

    		对话、动作与输出分列加权；短于 3 字符的词走有界补充检索。候选截断、未覆盖来源和解析失败显式返回。
    合同与入口共享 DTO + HTTP / CLI / MCP

    packages/shared/src/session-search.ts（拟新增）

    		同一分页、筛选、来源水位和上下文展开合同。Web 用现有 React，iOS 用 Swift DTO 对照协议。
    语言选择优先 TypeScript，SQLite 执行全文查询先量化 JSON 解析、I/O、数据库与 IPC 各阶段耗时；只有实际瓶颈与收益成立时，再评估 Rust 解析进程。

    先证明能查准，再把入口接齐。

    A / 固定证据与口径

    冻结一批真实历史

    • 复用本轮约 1.08 GB 历史与 10 个已定位事项，补充未命中、回退、嵌套工具和审核回放案例。
    • 目标会话与关键回执先人工核对，再运行检索；不根据结果倒选样本。
    • 记录原始哈希、解析覆盖、机器、版本与各阶段耗时。
    B / 数据与 Agent 入口

    解析 → 索引 → CLI / MCP

    • 先支持 Codex、Pi、Claude；格式不支持明确报出，不许静默吞掉。
    • 验证追加、截断、替换、分支回退、重复事件与未完成 JSON 行。
    • 验证 Worker 中断重启、事务一致性、缺失来源与索引重建。
    C / 人的阅读入口

    结果 → 上下文 → 原始证据

    • Web 接入会话归组、筛选、证据展开和覆盖提示。
    • iOS 使用同一 Backend 协议；真机交互单独验收。
    • 跨机器聚合、语义召回与自动交接另行评估，不提前扩展第一阶段。
    Top 5 · 10 / 10首批固定关键词题目标会话命中目标；随后扩展样本再报告泛化。
    p95 ≤ 100 ms热索引查询服务耗时的拟议目标；不含模型、首次建库和客户端渲染。
    关键回执 0 静默遗漏已知嵌套工具与历史回退案例必须正确表达；不支持则明确标记 partial。

    以上是验收目标，尚未实测。此前 ags 的约 19 ms / 41 ms 是进程启动到输出的平均值，不能直接与服务 p95 比较。新方案还须报告冷建库、增量追赶、峰值内存、磁盘与索引期间真实终端输入/WS 保活情况。

    本版建议采用

    • 当前 Backend 管理本机索引，默认当前仓库，可显式切换已授权项目。
    • 查询先读已提交水位，刷新由后台完成；陈旧与不完整状态可见。
    • 分块索引工具输出；超限要报告，不用“头尾截取”冒充完整覆盖。
    • 只索引原生会话正文；Activity、App Server 事件、Work History、日报和经验库不进入搜索输入。
    • 检索索引与经验库独立，保留各自的证据与生命周期。

    实现前细化，不阻止方案讨论

    • 来源登记与保留范围：原文件删除/撤回后清除对应正文索引，不能凭副本继续声称原文可读。
    • 更新频率与资源预算：按真实历史压测确定，不把文件通知当可靠日志。
    • 规范化与格式升级：解析版本变化重建受影响来源；未知来源不默认当作用户输入。
    • 界面入口位置可讨论；本页交互仅用于评审，不代表全部控件均进入首版。
