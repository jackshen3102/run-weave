# 终端长文本附件原型

交互演示用的历史原型，文件保存和投递均为模拟，不能作为产品验收证据。当前实现合同见
[Frontend](../../../frontend/docs/terminal-text-attachments.md) 和
[Backend](../../../backend/docs/terminal-text-attachments.md)。

## 查看

Runweave 的 Terminal 顶部菜单 → Prototypes → `terminal-pasted-text`。

独立查看：

```bash
python3 -m http.server 6188 --bind 127.0.0.1 --directory docs/prototypes/terminal-pasted-text
```

访问 `http://127.0.0.1:6188/`。默认展示附有一份长文本的草稿。
`?state=empty` 展示空草稿，`?state=preview` 直接打开附件预览。
这些 URL 参数是原型辅助功能，不进入产品。

## 原型简报

- 目标：把长文本粘贴为独立 txt 附件，输入区仍可编辑简短指令。
- 对应界面：现有 Terminal 桌面浮动输入框；沿用终端工作区、深色风格和青色发送按钮。
- 主要流程：粘贴至少 5000 个 UTF-16 单元的文本 → 附件卡片 → 预览、移除、放回输入框或发送。
- 关键状态：空草稿、普通文本、附件待保存、附件就绪、预览、正文恢复、发送后清空。
- 非目标：产品代码、真实 Backend 写文件、Agent 读取文件、远程上传及文件生命周期验收。

## 产品核心功能

| 元素 / 行为            | 用途                                           |
| ---------------------- | ---------------------------------------------- |
| txt 卡片、字符数和大小 | 不让长文本撑满输入区；每份附件可独立管理       |
| 点击卡片打开全文       | 发送前核对内容                                 |
| 移除附件               | 保留其他附件和指令                             |
| 放回输入框             | 在当前选区恢复全文，移除对应附件，避免重复发送 |
| 保存期间禁止发送       | 避免引用尚不可用的文件                         |
| 发送                   | 草稿和附件一起提交，之后清空输入区             |

## 原型辅助功能

| 元素 / 行为                          | 边界                                       |
| ------------------------------------ | ------------------------------------------ |
| mock-state.json 的终端会话和默认附件 | 全为样例，不读取用户会话                   |
| 650ms 保存延迟                       | 只表达加载状态，不进行实际 Backend 写入    |
| state URL 参数                       | 在 README 中说明，不在产品画面添加演示按钮 |
| 发送后追加本地终端消息               | 仅展示交互结果，不启动 Agent、不执行指令   |

`index.html` 是布局；`styles.css` 是样式；`app.js` 是独立状态机；`mock-state.json` 是样例数据。
没有导入生产源码。附件仅保存在页面内存，刷新即重置。

## 验证点

- 首屏附件预览、关闭、移除、恢复；正文、换行和 emoji 不丢失。
- 4999 单元普通粘贴；5000 单元转附件，原指令保留。
- 同长度多次粘贴生成独立附件；只含附件也可发送。
- 保存期间不可发送；发送后卡片与正文清空。
- 窄窗口不产生横向溢出。

## 当前设计决策

采用桌面端的真实 txt 附件交互，未采用 CLI 的内存占位符方案。
附件由目标 Backend 管理；真实文件生命周期、草稿与失败恢复以当前实现合同为准。
原型没有承诺文件路径插入格式、模型上下文处理方式或真实远程可读性。
模拟状态不代表真实 Agent 或远端文件读取通过。

## 本轮验证结果

通过仓库锁定的 Playwright CLI 1.62.1，在当前 Terminal Browser 的 Profile 1 中新建独立标签页验证。
14 项交互断言通过：预览全文一致、恢复全文保留指令、恢复后移除附件、4999 单元不拦截、
5000 单元转附件、保存中禁发、正文保留、同长附件独立、定向删除、仅附件可发、
发送携带正确附件、发送后清空、保存中移除不会重新出现、390px 窄窗口无横向溢出。
粘贴使用浏览器 ClipboardEvent 分发验证，未声称操作系统剪贴板端到端验收。
控制台没有错误或警告；`pnpm docs:check` 通过。

截图：[主界面](./prototype-preview.png)、[全文预览](./attachment-preview.png)。
页面保留的操作只包括预览、移除、放回输入框及发送，没有扩展文件管理操作。

## 2026-09-30 双入口补充

`?mode=tui&state=empty` 演示浮动输入框关闭时直接粘贴：保留已有草稿，保存后只插入带空格边界的 JSON 路径，没有提交回车。`state=saving` 将保存停留 60 秒；保存期间继续输入会使路径未插入。`state=changed` 模拟目标变化。

提示可预览、复制原文和关闭。关闭提示不撤回 TUI 引用。浮动入口恢复正文仅替换当前选区。此原型的文件、输入和目标变化仍为模拟，不能作为产品或 Agent 文件读取验收证据。

补充原型浏览器验证：TUI 保存成功、目标变化取消、继续输入取消、全文预览、关闭保留草稿及保存中关闭不阻止路径插入均通过；未计入产品验收。
