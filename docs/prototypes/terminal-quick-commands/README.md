## 原型简报

- 用户目标：从终端页面直接执行常用指令，并看清当前电脑所有项目的后台任务。
- 入口：在终端、变更、文件之后增加快捷指令 Tab。
- 上方看板：展示跨终端、跨项目的后台快捷指令任务，最多 3 条；更多进入全部列表。
- 执行位置：始终为当前终端对应的项目或 worktree，不提供选择器。
- 任务身份：按每次运行展示；执行位置由 projectId 标识，不按发起终端 ID 分组。
- 下方指令：沿用全局库和手动排序，不另建收藏体系；支持新增、全文、编辑、删除、排序。
- 高频操作：发送到当前终端、独立后台运行。插入输入框放入管理菜单。
- 主要流程：后台提交后留在本页，看板出现排队任务；直接发送后回到终端；插入则打开输入框，不发送。
- 关键状态：运行中、排队中、停止中、已停止、无后台任务、当前项目已有同一指令在运行。
- 非目标：实现真实运行、跨电脑聚合、执行位置选择、重新设计终端/文件/变更页面、修改模型设置。

## 视觉与布局

沿用当前 iOS `TerminalAppearance` 的背景 #101316、面板 #20272b、薄荷绿 #a5d9c9，终端标题、连接状态、Tab 下划线及底部安全区域。执行按钮高度至少 44px。

看板按运行中、停止中、排队中分组，组内保留新到旧的顺序。每行两层：指令标题及状态/耗时，执行项目/worktree。首页不放输出和停止按钮，点击整行进入详情。

指令卡片使用单排紧凑布局：左侧标题与单行正文预览，右侧发送、后台/查看和管理菜单。操作按钮的视觉高度为 30px，实际点击高度保留 44px；卡片约 62px 高。常用指令通过手动排序放在前面，不另分重复列表。原型排序用上移/下移表达手动顺序；正式 SwiftUI 页面应沿用现有拖动排序交互。

## 产品核心功能

| 元素 / 行为                | 产品价值             | 当前代码与差异                                    |
| -------------------------- | -------------------- | ------------------------------------------------- |
| 文件后的快捷指令 Tab       | 常驻入口             | 现有 TerminalScreen 有三个 Tab，需新增页面        |
| 全局任务看板，最多三条     | 跨项目观察执行       | 后端允许省略 projectId，iOS 当前按项目过滤        |
| 全部任务二级列表           | 首页保持紧凑         | 展示每次 run，不沿用每条指令仅保留最新 run 的缓存 |
| 项目/worktree 标签         | 区分任务执行位置     | 使用 run.snapshot.origin 及 executionProjectId    |
| 当前执行位置提示           | 执行地点无需选择     | 使用当前终端的 projectId，包括 worktree 项目 ID   |
| 一键发送到终端             | 高频直接执行         | 新入口应接入现有输入提交能力，保留编辑器已有草稿  |
| 一键后台运行 / 查看运行    | 独立执行及防重复提交 | 沿用 quick-input start、projectId 与幂等合同      |
| 插入输入框                 | 少量需要编辑的场景   | 沿用现有插入能力；原型无原生光标与选区            |
| 全文、增删改、排序         | 管理现有指令         | 沿用现有全局库能力                                |
| 运行详情、配置、输出、停止 | 查看和处理任务       | 沿用 ScheduledRunView 与现有 API 能力             |
| 无任务及无指令反馈         | 日常空状态           | 原型表达页面布局                                  |

同一指令在其他项目运行，不阻止当前项目启动；同一指令在当前项目已有活动运行，后台按钮改为查看运行。看板范围为当前连接电脑的后台快捷指令任务，不包括所有定时任务或终端前台执行。

后台运行使用独立 Codex 任务及后台默认模型，不继承当前终端会话。运行详情展示这一配置，不把权限或模型选择加入执行流程。

## 原型辅助功能

| 辅助内容                        | 用途                 | 不进入产品的原因                       |
| ------------------------------- | -------------------- | -------------------------------------- |
| JSON 中的任务、耗时、输出、模型 | 展示真实结构的样例   | 全部模拟，不代表实际账号配置或执行结果 |
| URL 场景参数                    | 查看不同状态         | 不属于产品控件，不出现在画面           |
| 直接发送后的“已接收指令”        | 表达提交后的终端位置 | 无真实 Agent 响应，不证明后端输入完成  |
| 900ms 后的停止完成              | 展示状态变化         | 实际实现需以后端进程状态为准           |
| 状态栏和浏览器手机外框          | 展示原生整体观感     | iOS 由系统提供，不重复实现             |

场景地址：

- `?runs=5`：五个任务，首页仅三条，其余进入全部。
- `?empty=1`：没有后台任务。
- `?project=main`：当前执行位置为主项目，看板保持全局。
- `?terminal=other`：同项目另一个终端，同样的全局任务。
- `?view=detail`：打开首条运行详情。

辅助功能不增加产品范围。刷新即恢复样例，编辑与提交均不持久化。新后台任务保持排队状态，不模拟完整 Agent 执行。

## 调整与冻结

第三轮：用户指出卡片和按钮过大，改为约 62px 高的紧凑单排卡片；正文只显示一行，点标题查看全文。发送与后台按钮视觉高度缩至 30px，保留 44px 点击高度。

第二轮：用户明确指令始终只有少量几条，移除搜索入口、筛选逻辑及对应样式；指令卡片直接接在执行位置下面。

初稿采用全局看板与单一指令列表；没有采用独立常用区、执行地点选择器、首页停止按钮、首页实时日志、自动排序。

2026-10-01 用户确认紧凑版原型并授权实现、模拟器测试。交互已冻结，产品核心功能与 URL 辅助功能按上表区分；实现按当前产品代码展开，当前合同与源码入口见 [iOS 快捷指令架构](../../../packages/app-ios/docs/architecture.md#backend-全局快捷指令)。
