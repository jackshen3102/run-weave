## 实际实现

旁聊仍由 Codex `rust-v0.160.1` 的 `/side`、`/btw`、Ctrl+/、空输入 Ctrl+C 管理，复用同一终端和进程。适配补丁只发布 TUI 拥有的主身份、当前显示身份和输入状态，并在原生事件循环中校验、执行宿主输入。没有第二套聊天运行时，也没有持久旁聊终端。

Runweave 将主身份用于恢复、完成和监督，将显示身份用于浮动草稿、附件和输入目标。关闭旁聊不会改变主恢复目标；`/new` 和 `/resume` 仍可改变主身份。浏览器重连保留活着的原生旁聊，CLI 重启只恢复主会话。普通 Fork 保持独立持久终端。

真实验收中另外修复了三个缺口：panel 更新去重丢弃身份变化；150 ms 输入延迟回退抢走原生焦点并重放草稿；自动恢复硬编码全局 `codex`，未使用已配置的受管可执行文件。均在修改后重新验证相关路径。

提交材料中的文字记录已将本机用户目录替换为 `<USER_HOME>`；事件、会话 ID 和结果保持原值。截图保持原始像素，原始文字备份仅留在本地恢复快照。

SIDE-014 的固定原生基线没有关闭 Side 能力的配置开关，因而没有声称验证“关闭开关”或旧版二进制。能力缺失采用自有暂停进程的观测协议版本故障注入，原文件在 finally 中恢复并继续进程。这证明受管输入的拒绝路径，不证明其他版本 Codex 的行为。15 项结果仅适用于以上实际执行范围。

## 检查与边界

shared、Backend、Frontend typecheck；Backend/Frontend lint；架构检查；终端生命周期与 scheduled runtime 既有验证；Hook 构建同步与验证均通过。记录保存在 [证据目录](managed/)。未新增单元测试。文档链接和 YAML schema 校验不计入 UI 验收。

仅支持当前固定受管基线和本机 macOS 构建。未启用受管版本的官方 CLI 保持旧接入方式，不宣称拥有身份隔离。受管交互使用 `--no-daemon`，不支持共享 daemon 的 `codex agents` 总览及 `--remote`。不是 Codex 桌面端内部实现复刻，也未扩展 iOS、Diff 或远程执行器。

原生创建、权限、切换、取消依然遵循 Codex；自定义按键以原生配置为准。错误或回执超时保留草稿并要求用户核对终端，不自动重发。启用需按合同配置 `agents.codex.binary` 并重启对应实例；本次仅在隔离实例启用。
