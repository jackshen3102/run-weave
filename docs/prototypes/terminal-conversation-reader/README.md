# 终端会话阅读原型

2026-10-04 的历史设计讨论产物。HTML mock 仅表达布局和状态，不代表真实产品验收；当前实现与边界以[活文档](../../architecture/terminal-code-preview.md#agent-会话阅读)为准。

## 原型简报

目标：主动阅读当前 Agent 会话，按顺序浏览提问和回答，改善长回复阅读体验。

Web 从终端的「阅读会话」进入右侧面板，可展开阅读。移动端从同一入口进入全屏阅读页，返回按钮回到终端。两端共用连续的正文布局，每轮提问在前、回答在后，整页共用滚动区域。

打开时读取一次；之后只有点击「刷新」才全量重读当前会话。刷新时保留阅读位置，用稳定轮次锚点避免新增内容将页面拉到底部。「回到最新」由用户主动触发。重复刷新不重复插入轮次。

提取用户提问、Agent 对用户可见的阶段说明和回答；过滤思考过程、工具调用和工具结果。历史范围取决于原始记录，不承诺永久完整。默认只读当前 thread，不跨 thread 拼接。

## 打开方式

在 Runweave 的 Prototypes 中选择本目录。脱离 Runweave 时：

```bash
python3 -m http.server 6198 --bind 127.0.0.1 --directory docs/prototypes/terminal-conversation-reader
```

- Web：`http://127.0.0.1:6198/`，建议 1440 × 1000。
- 移动端：同一地址，使用 390 × 844 视口。表达原生 iOS 全屏阅读的布局意图，仍是浏览器 HTML 原型。
- 入口：`?view=terminal`，点击「阅读会话」。
- 展开：点击「展开阅读」，或使用 `?expanded`。
- 空状态：`?scenario=empty`。
- 刷新失败：`?scenario=refresh-error`，点击刷新，原正文保留，可再次操作。
- 双端对比：`compare.html`，原型展示板以 iframe 并排放置两个产品画面，展示板本身不是产品界面。

## 功能分类账

| 类型     | 内容                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 产品核心 | 连续问答、Markdown 正文、手动全量刷新、读取中/读取成功/无变化/失败反馈、阅读位置保持、回到最新               |
| 产品核心 | Web 右侧阅读/展开/关闭，移动端全屏阅读/返回终端                                                              |
| 原型辅助 | mock-state.json、固定时间、首次刷新增加第 4 轮、URL 空状态/失败状态参数、手机状态栏图形、compare.html 展示板 |

辅助内容不进入实施范围。画面中没有模拟控制台、演示按钮或需求说明。

## 数据与边界

- 无构建、无外部依赖。模板来自 prototype-first-development 技能的 HTML 模板。
- 所有正文来自 mock-state.json；首次点击刷新模拟读取到第 4 轮，此后刷新显示内容无变化。
- 650ms 延迟只表现手动读取的等待状态，不代表真实读取耗时。
- 原型没有轮询，没有后台订阅，没有 localStorage、数据库、正文备份或原始文件写入。
- 原型 Markdown 渲染只覆盖样例的段落、标题、列表、表格、引用和代码；最终复用产品已有渲染器。
- 移动端顶部刷新按钮为图标，Web 同时显示图标和文字；均带可访问名称「刷新会话」。
- 原型表达返回/重开布局；真实实现必须每次打开都重新读取源数据，不能把 fixture 重显当成该能力已实现。

## 已收敛的选择

保留：主动阅读、手动全量重读、当前 thread 内多轮提问/回答、原始记录作为唯一正文来源。

放弃：每隔几秒轮询、自动滚动追踪进度、新增历史存储/备份、只显示最近一条回复、只为阅读另写飞书文档。

- [会话详情合同](../../../packages/shared/src/app-server/events.ts)已有按轮次的用户/助手正文结构。
- [原始记录预览读取器](../../../app-server/src/agents/thread-previews.ts)已有 Codex/Pi JSONL 读取和过滤，但只保留最新一轮的短摘要，不能直接当作全文历史接口。
- [Codex 详情读取](../../../app-server/src/codex/client.ts)使用 thread/read 获取轮次；未在本次验证它对进行中回复的可见时机。

上述为原型阶段的差异记录，不能作为当前待实施清单；当前产品链路和验收入口见活文档。

## 验证

通过仓库固定版本 Playwright CLI，附着解析得到的 Profile 1，并新开原型 tab 保留原有页面。验证范围是浏览器 HTML 原型，不代表原生 iOS 真机验收或真实 thread 接入。

| 验证点            | 结果                                                       |
| ----------------- | ---------------------------------------------------------- |
| Web，1440 × 1000  | 首屏 3 轮；刷新后 4 轮；前三轮正文不变；读取期间按钮禁用   |
| Web 阅读位置      | 刷新前后均为 410px；重复刷新无重复轮次，并反馈内容无变化   |
| Web 导航          | 展开、收起、关闭、重新打开、回到最新均通过                 |
| 移动端，390 × 844 | 无横向页面溢出；底部状态栏保留在视口内                     |
| 移动端阅读位置    | 刷新前后均为 370px；刷新、返回终端、再次进入、回到最新通过 |
| 可恢复状态        | 刷新失败保留原正文且恢复按钮；空状态显示暂无对话           |
| 文档检查          | pnpm docs:check 通过                                       |
