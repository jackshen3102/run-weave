一、机制 2（第一阶段）：Review changes 相对主分支 Diff 与本分支提交

解决 Agent 执行 git commit 后工作区变空、桌面与手机无法继续在应用内审阅本分支完整改动的问题。全程纯只读 Git 查询。

原型演示切换（非产品按钮）：
Preview · Review changes wt-1 (feat/branch-diff)

协议与代码落点

  • packages/shared/src/terminal/preview.ts：新增 scope: "working" | "branch" | "commits"，返回锁定的 baseRef / mergeBaseOid / headOid。
  • backend/src/terminal/preview/git.ts：复用 HomeBranchStatusService 的远端基准解析；branch 模式对比 mergeBaseOid → working tree（含未提交与已提交净变更），commits 模式列 mergeBaseOid..HEAD 最多 50 条本地提交。
  • frontend/.../preview/changes/ 与 packages/app-ios/.../Preview/：顶部分段切换，branch/commits 下隐藏单文件 Reset/Delete 写操作。

关键边界与验证

  • 不隐式改状态：切换 scope 不执行 git fetch 写工作区，仅在手动刷新时更新远端跟踪引用。
  • 一致性保护：点开单文件 Diff 时携带列表返回的 mergeBaseOid（或 commitOid）；期间 rebase 导致 OID 变化返回 409 terminal_preview_stale_diff。
  • 无阶段二包袱：不创建 .git/t3-checkpoint-indexes、不写任何隐藏 Git Ref。

二、机制 3：一键新建 Worktree 终端 + runweave.json 受控 setup

将 RaceWorktreeSupply 抽为公共服务，支持在桌面 Worktree Rail 与手机首页「＋」直接拉起新分支 Worktree，并在受控确认后执行初始化脚本。

原型演示切换：
main (主目录) wt-1 · feat/suiji wt-auth-refactor · 新建中 ＋ 新建 Worktree

runweave.json 最小扩展合同

  • 在现有 schemaVersion: 1 下新增可选顶层字段 worktree?: { setup?: { command: string; cwd?: string } }，复用 WorkspaceServiceConfigLoader 的非符号链接、256 KiB 与目录边界校验。
  • Backend 在当前 Profile 存储 (repositoryId, setupSha256) 批准记录；命令一字未改时后续新建免重复弹窗，改动任意字符立即要求重新确认。

接口与代码落点

  • 新增 POST /api/terminal/project/:parentProjectId/contexts（参数：name、branch、baseRef、launchAgent?、approvedSetupRevision?、operationId）。
  • 抽离 backend/src/race/race-worktree-supply.ts 公共校验至 backend/src/terminal/workspace-service/worktree-provisioner.ts；更新桌面 worktree-rail.tsx 与 iOS 首页上下文选择 Sheet。

三、机制 4：Attention 待处理收口 + Working 折叠 + PR 有界值守

把散落在各处的「真正在等人拍板」信号统一收进 needs_action 置顶，默认折叠正在跑的终端，并提供防死循环的后台 PR 值守。

四、机制 5：跨 Agent / 跨 Worktree 有预算上下文交接（Portable Context Handoff）

五、机制 6：Agent 启动上下文与 MCP 工具字节预算门禁

每次会话启动都会隐式加载根 AGENTS.md、Toolkit 技能列表摘要与 MCP 工具定义。用确定性字节预算文件锁死上限，防止日常迭代无感膨胀。
