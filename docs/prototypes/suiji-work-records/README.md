# 随记工作记录交互原型

状态：2026-10-24 用户确认的历史设计快照。当前工作事实合同与边界见[随记架构](../../architecture/suiji.md#独立工作事实)和[服务入口](../../../packages/suiji-server/README.md#工作事实schema-10)；正式功能以真实代码为准，原型不代表生产已经部署。

## 本轮采用的简化方案

一期阅读入口只做两件事：按日期倒序看事实，需要时按日期筛选。进入工作页直接看最近一天的事实，再向下看更早的日期；当天有已导入记录时当天在最前，没有当天材料时从最近的实际记录开始，不虚构今天的空日结论。

主视图不再放搜索框、项目/类型下拉、日周月切换、周内日期条或月历。日期、项目和类型不是一组始终占据首屏的工具栏。右上角保留一个「日期」入口，点开后只选开始日期和结束日期；同一天可将两端设为相同日期。支持单边日期、取消、清空和恢复全部记录，拒绝起始日期晚于结束日期。已应用的日期条件显示一行，可一键清除。

每日标题显示「今天／昨天／前天／实际日期」和真实条数，内容按天倒排，同一天内保留事实卡片。项目只作为记录上的轻量信息。周报候选从详情中选择，不在每张卡片上常驻复选框。人工置顶只影响同一天内顺序，不跨日期打乱记录流。

未采用上一版的筛选面板首页、日历首页、按项目折叠阅读和复杂的日周月阅读控制。没有为一期增加高级检索、AI 总结或新的自动采集能力。

## 电脑端与手机采用同一窄屏界面

已核对 `frontend/src/features/suiji/drawer.tsx`：现有电脑随记是右侧 480px 抽屉，最大宽度为窗口宽度，不是独立大屏工作台。原型按这一边界调整，移除电脑专用侧栏及大屏内容布局；窗口加宽只增加抽屉外的宿主区域，不扩大随记内容。

`index.html` 仅承载抽屉，`content.html` 是电脑与手机共用的唯一内容页面，`app.js` 是同一套交互。在电脑上抽屉固定 480px，内部进入手机布局；手机上同一内容铺满屏幕。底部导航、事实倒排、日期弹窗、补记、详情与归类均相同。弹窗、底部导航和悬浮按钮限制在抽屉内部；关闭后重开保留页面状态和未提交的日期输入。内部弹窗优先响应 Escape，之后 Escape 才关闭抽屉，也支持顶部关闭和点击抽屉外关闭。

电脑宿主工作区在原型中以空白背景省略，没有伪造终端内容、项目或工作事实；不从这片空白推断真实 Runweave 布局。电脑多出的仅是抽屉开合，不增加大屏分类、额外筛选或独立交互模式。

## 手机入口和次级功能

已核对当前 iOS 源码 `packages/suiji-ios/Sources/SuijiIOS/App/SuijiRootView.swift`、`Features/ReviewView.swift`、`Features/RecordDetail.swift` 与主题组件。当前正式代码底部是「记录 / 待办 / 回收站 / AI」，AI 页实际是按需提问的「AI 回顾」。本轮基于源码，未核对用户手机安装版本。

原型继续采用「记录 / 待办 / 回收站 / 工作」，替换第四个 AI Tab，默认仍进入记录。点「工作」进入倒序事实流，右下角加号用于补记；顶部更多中保留此前评审过的重新归类、周报草稿和 AI 回顾，作为次级能力，不扩展本轮一期阅读范围。记录详情仍保留「聊聊这条」，携带单条范围并可返回原详情。AI 不连接模型，不生成回答。

周报草稿是二级页面。详情可加入周报候选，已有选择时浮条可进入选材。只编排选择的原文，保留日期和状态，不调用模型。保存的草稿与事实相互独立。

## 项目与重新归类

新补记项目可选，默认空白，按「未归类」保存。项目名称从当前事实去重获得，没有接入项目库，也没有已验证的自动业务分类器；已有的四个归类来自 Agent 阅读材料后的整理。

单条入口为「事实详情 → 重新归类」，批量入口为「工作 → 更多 → 重新归类」，桌面也有页头按钮。可跨日期勾选或全选当前日期范围内的结果；归类选择与周报候选独立。提交前列出选择范围、原日期和原项目，允许选择已有名称、填写新名称或留空退回未归类，可取消和撤销。

归类只修改项目，不修改事实身份、事项身份、标题、正文、日期、状态及来源，也不自动合并或删除记录。已保存周报的正文和选材快照不跟随修改，重新整理时采用最新归类。正式实现仍需持久化人工归类，防止采集覆盖用户修改。

## 真实数据与边界

`mock-state.json` 沿用模板文件名，包含实际核对的 2026-10-21 至 23 日 24 条事实，逐日 7、9、8 条。正文、日期、项目、事项身份和状态与原始事实逐项一致，标题只是实际事项的短名称；项目为 CCM 性能实验室 17 条、Office 静态资源防劣化 5 条、豆包 Office 和 Harness 各 1 条。没有虚构记录、默认选材或草稿。

日期相对名称以材料快照的 2026-10-24 为准。只有这三个日期已导入，查询未导入日期时明确说明尚未导入，不写成当天什么都没做。原始材料和内部引用留在受保护的本机 daily-record 目录，不把来源编号、原始消息或鉴权 URL 放到工作记录正文中。

既有记录/待办页仅提供入口上下文，使用服务实际返回的「工作」标签 9 条完整记录（5 条未完成、4 条已完成），不是全量随记首页。回收站未读取，不伪装为空。连接设置、普通记录编辑、待办状态修改和回收站恢复未在原型重建。

原型不连接随记生产服务。补记、编辑、归类、置顶、选材与草稿只保存在当前浏览器 localStorage，键为 `suiji-work-records-prototype-20261024-v2`，不跨设备同步。旧版原型的事实、选材和草稿保留，阅读布局迁移时重置旧筛选条件。浏览器开发工具可删除该键重置，不在产品画面放辅助重置按钮。

## 功能分类

| 产品核心功能   | 原型行为                                         |
| -------------- | ------------------------------------------------ |
| 倒序事实流     | 按实际工作日期从新到旧直接展示内容，点标题看全文 |
| 日期筛选       | 次级弹窗选择起止日期，支持清空、取消和范围校验   |
| 补记与编辑     | 可选项目、工作日期、正文和状态；重复新增保护     |
| 人工归类       | 单条或批量调整，提交前核对，可撤销，只修改项目   |
| 周报选材与草稿 | 从详情选材，原文编排，独立保存和复制             |
| AI 回顾入口    | 次级入口及原记录上下文；不连接模型               |

原型辅助：静态 JSON、浏览器 localStorage、内联数据副本和 URL 参数 `?view=work`、`?view=work&date=2026-10-22`。不把这些实现方式或未接通的服务推断为正式产品已有能力。辅助信息仅在本文件，不进入产品画面。
