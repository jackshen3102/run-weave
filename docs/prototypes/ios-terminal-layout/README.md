## 原型简报与现状

目标是在手机上平衡终端输出阅读、短指令输入、TUI 按键与文件检查。暂按“手机查看 Agent 输出，同时频繁补充指令”的场景设计；用户尚未确认此行为优先级。

本轮打开现有 iOS 模拟器里的原生 Runweave，进入已连接的 Codex 会话，并查看了空草稿获得焦点后的状态。没有发送远程输入。模拟器没有弹出软件键盘，不能把原型键盘当成真实设备验收。

真实代码：

- [TerminalScreen.swift](../../../packages/app-ios/Sources/RunweaveIOS/Features/Terminal/TerminalScreen.swift)：导航、路径/状态、Chat/Changes/Files、终端、快捷键与 Composer 纵向排列。
- [ComposerView.swift](../../../packages/app-ios/Sources/RunweaveIOS/Features/Terminal/Input/ComposerView.swift)：媒体入口独立占一行；竖屏草稿固定 70 高；发送/停止共用动作位置。
- [CommandTextView.swift](../../../packages/app-ios/Sources/RunweaveIOS/Features/Terminal/Input/CommandTextView.swift)：背景透明，没有可见 placeholder。
- [ShortcutBar.swift](../../../packages/app-ios/Sources/RunweaveIOS/Features/Terminal/Input/ShortcutBar.swift)：六个等宽文字按键，直接发送终端控制序列。

观察：顶部路径截断后难以辨认；导航、状态、页签和底部多个操作行没有形成稳定层次；草稿没有视觉边界；Enter/Ctrl-C 与草稿发送属于不同输入语义，布局需要区分。原始 TUI 自身的线条、颜色和输入提示也会影响观感，不能通过重绘外壳自动消除。

## 四个方向

| 方向                     | 核心思路                                                     | 收益                                 | 代价                                                                                   |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------ | -------------------------------------------------------------------------------------- |
| 1. 原结构精修            | 不动区域顺序，统一间距、字阶和按钮形状，给草稿加边界         | 最少改变习惯，工作量最小             | 上下分层仍多，空间收益有限                                                             |
| 2. 底部操作台 A          | 两行标题取代独立路径状态行；按键和草稿形成整体；媒体放草稿内 | 草稿边界清晰，收起按键时输出区域更大 | 使用快捷键前需要聚焦并点一次展开                                                       |
| 3. 专注终端 B            | 单行草稿常驻，按键与工作区按需展开                           | 输出空间最大，视觉最安静             | 按键、变更、附件部分操作增加一步                                                       |
| 4. Agent 对话 + 原始终端 | 将结构化 Agent 事件呈现为对话，并保留原始终端切换            | 对纯 Agent 任务更易读                | 不只是 UI 重构；必须先验证事件合同，不能靠解析 ANSI 文本保证正确；shell/TUI 仍需原终端 |

用户已选择 A。当前调整：未聚焦为单行，顺序是左侧加号、中间草稿、右侧语音和发送；聚焦后展开多行编辑区，下方才出现快捷键开关；点击展开，再点收起，展开时按钮高亮。开关不唤起或收起软件键盘，不清空草稿，不丢失输入焦点；原先位于终端底部时仍跟随底部。B 仅保留作历史备选，不作为当前落地方向。

## 行为与分类

产品意图：原始终端保持连续；草稿有明显边界；发送后才清空；停止与有草稿时的发送区分；图片/转写只追加草稿；断线保留草稿并禁用发送；低频/危险操作进入菜单；快捷键与草稿发送不合并。

原型辅助：mock-state.json、URL 状态参数、绘制的键盘、固定时钟、示例文件与终端输出、compare.html、预览 PNG。全部是演示数据/布局占位，不进入产品实现。

可交互：草稿输入、模拟发送/停止、快捷键展开、文件/变更导航、菜单、模拟附件/语音追加、断线恢复。

未实现：真实终端渲染/选区/滚动恢复/ANSI/尺寸协商、真实文件打开与 diff、剪贴板、系统键盘/语音/图片权限、真实网络。快捷键反馈与发送成功均是本地模拟；草稿仅驻留内存。文件行只展示视觉结构。

字体使用 14px 等宽字体表达可读性目标；原生落地须由 SwiftTerm 真实字体、Dynamic Type、安全区、横屏和不同键盘验证。不得为了装下内容而缩小终端字体。键盘外观与 270px 高度只是占位。

## 验证记录

通过仓库固定版本 `pnpm exec playwright cli`，附着当前 Worktree 解析出的 Profile，使用新标签验证原型，不复用或覆盖用户已有页面。

浏览器验证覆盖：390×844 无页面横向溢出；A/B 输入、发送清空、停止；A 变更切换、图片追加；B 按键展开与语音追加；断线禁用发送且重连保留草稿。430×900 保存三个预览。结果属于 HTML 原型，不能代表 SwiftUI 或真机验收。
