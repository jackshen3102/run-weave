# Agent 定时任务交互原型

2026-09-21 第三轮设计产物，现作为历史交互原型冻结。当前实现与限制见[定时任务接入](../../../frontend/docs/scheduled-tasks.md)；下文模拟行为不代表真实调度、终端恢复或多端同步。

## 打开

在 Runweave Terminal 顶部 `... → Prototypes` 中选择 `agent-scheduled-tasks`，或独立运行：

```bash
python3 -m http.server 6188 --bind 127.0.0.1 --directory docs/prototypes/agent-scheduled-tasks
```

打开 `http://127.0.0.1:6188/`。页面通过相对路径加载数据，需要 HTTP 服务。

## 原型简报

面向文档整理、代码优化、调研分析三种场景。Backend 持有任务和运行记录，各客户端连接同一 Backend 管理；原型仅表达这个产品意图。

本轮根据用户提供的手机参考图简化页面：任务卡片只展示名称、提示词摘要、项目、Agent、时间和启停开关；运行、编辑、删除收进更多菜单。详情展示配置和运行历史。点击一次运行进入现有普通终端，可以继续追问；原型里的终端画面仅代表示意，不新增产品终端组件。桌面双列卡片，手机单列；创建表单在手机以底部面板呈现。

沿用用户确认的边界：

- 配置名称、项目、Agent、提示词和时间安排；模型与推理强度在高级设置中。
- 不提供 worktree 开关。创建目录、隔离工作区、提交 PR、发布飞书文档由提示词或 Skill 引导。
- 每次运行产生独立对话。产物可以是代码、文档或文字结论，不要求修改文件。
- **自动运行只保存运行记录和 thread ID，不自动创建项目终端。** 用户打开某次运行时才创建终端并恢复该对话；已经打开过则复用同一终端。
- 终端归属本次对话对应的项目或 Worktree，沿用现有创建、打开、输入、恢复与生命周期能力。不是随当前浏览器所选项目迁移运行，也不由调度器强制新建 Worktree。
- 终端只增加可选的 `source` 元数据。当前原型用 `{ type: "scheduled-task", taskId, runId }` 表达来源；未来其他类型按需扩展，不提前实现来源注册框架。
- 来源不替代已有的项目归属、工作目录和 thread 字段。终端中只有轻量的“来源：任务名称”入口，回到任务详情并突出本次运行；移除定时运行专属状态栏，状态留在历史记录中。
- 项目列表只展示实际打开过的终端，未打开的运行记录留在任务详情中，不计入终端数量。示例中的文档整理运行归属 `docs-maintenance` Worktree，调研运行归属 Research 项目。
- 继续追问属于原对话，不会把已完成的定时运行重新标成运行中；等待用户补充的运行可以在补充后继续完成。
- 打开尚在执行的运行先查看输出，执行结束后可追问；不同时启动第二个 Agent 恢复同一 thread。

## 产品核心功能（待评审）

| 行为       | 本轮设计                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------- |
| 查找与管理 | 按当前 Backend 隔离任务，支持项目筛选、搜索、启停                                        |
| 创建与编辑 | 每天、工作日、每周多选日期、仅一次；显式时区及下次时间预览                               |
| 任务详情   | 配置卡片、可展开提示词、运行历史；历史保留当时的配置快照                                 |
| 立即运行   | 新增运行记录及独立 thread；不新增终端；同任务未结束时禁用重复启动                        |
| 暂停与停止 | 暂停只影响后续安排；停止当前执行需确认                                                   |
| 打开运行   | 首次按需创建终端并恢复对话，再次打开复用；完整页面内查看输出、产物和继续输入             |
| 项目入口   | 复用项目终端列表找到已打开的对话；终端保留通用来源入口；项目或 Worktree 归属沿用现有模型 |
| 删除任务   | 确认后移除后续安排；保留已打开终端及底层历史数据，不终止正在执行的运行                   |
| 状态       | 排队、执行、等待处理、完成、失败、停止、空列表、后端离线                                 |

Web 主入口已确认放在终端工作区顶部，与“随记”并列。归档、补跑、并发、运行中查看与 provider 恢复的实施规则见 [当前接入合同](../../../frontend/docs/scheduled-tasks.md)及[运行配置](../../deployment/overview.md#定时任务运行)；原型未模拟全部实施边界。

## 原型辅助功能（不进入产品范围）

- `mock-state.json` 提供虚构任务、运行、产物和固定时钟 `2026-09-21 10:30 Asia/Shanghai`。
- LocalStorage 保存本浏览器内的数据、thread 和按需生成的终端标识，不代表 Backend 持久化。
- 手动运行约 0.9 秒后进入运行中，再约 6.5 秒完成；追问约 1.3 秒返回预设文本，没有调用真实 Agent。
- 终端视图是 HTML 占位，实施时复用现有终端界面，不移植此占位组件；没有创建 PTY 或真实恢复 provider thread。运行中的输入暂不可用，避免表现成重复启动会话。
- PR、飞书入口展示本地产物预览，不访问虚构外部链接；授权补充也只模拟流程。
- 页面内不放演示控制台和教程说明。URL 可准备评审状态：`?reset=1` 重置数据、`?theme=light` 浅色、`?backend=server` 空后端、`?backend=remote` 离线、`?empty=1` 空列表。
- 路由：`#tasks`、`#task/docs`、`#projects`、`#terminal/docs-0921`。终端深链接也会按需打开。重置之后应移除 `reset` 参数，避免刷新再次清空。

## 冻结状态

本轮采用：简洁卡片、详情内历史、在所属项目或 Worktree 下按需打开普通终端、可选 source 元数据及来源回跳。放弃：独立的定时任务终端实现、专属运行状态栏、每次运行自动新增终端、多面板同时展开、单独的恢复确认步骤。

用户已接受核心方案并要求先做 Web 实施计划；iOS 延后。本轮没有修改产品实现，原型辅助功能不进入实施计划。
