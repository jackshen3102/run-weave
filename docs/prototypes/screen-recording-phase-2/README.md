# 屏幕记录二期：时间回放图片原型

日期：2026-10-31。状态：设计讨论稿，未冻结，尚未实现。

实施依据已整理为[二期实施计划](../../plans/2026-10-31-screen-recording-phase-2.md)。图片仍保留旧的应用标题示意，实施时改为时间段主标题、“当前帧前台应用”副标签；大画面展示所选显示器整屏，不是单应用窗口截图。应用分组、协议和在线有效性以实施计划为准，不从旧图反推。

按用户“先用图片也行”的要求，本轮交付静态图片原型，暂不创建 HTML 或产品页面。图片由图像工具生成，里面的桌面内容和记录均为示例，不包含从用户采集库读取的真实截图。图像不是现有 App 截图，不证明网络、界面或原生交互已经实现。

## 用户目标与流程

在 Runweave iOS 中查看 Mac 最近保存的屏幕记录：选择日期与时间段，播放快速回顾，暂停后通过缩略图时间轴定位某张画面。Mac 端也提供本地回放。仅在线访问，原始记录默认保留 7 天，实际可用范围受容量与采集情况影响。

一期采集继续独立运行；二期不引入 AI 总结、OCR 搜索、随记写入或离线浏览。

## 手机设计

图片：[iOS 原型](ios-concept.png)。三个画面分别为时间线、时间回放和连接中断。

- 入口建议放在 Runweave 首页现有更多菜单，与“Mac 桌面”等功能并列，命名“屏幕记录”；不新建手机 App 或底部导航栏。图片从进入该功能后的页面开始。
- 深色原生界面，与当前 Runweave iOS 默认主题一致；顶部显示当前 Runweave 连接对应的 Mac 和连接状态。复用已有连接选择，不增加 ScreenJournal 单独登录、扫码配对或独立令牌。
- 日期选择以最近可用日期为主，显示实际可查看范围，不把默认 7 天承诺为完整无缺的 7 天数据。
- 列表按时间排列，以时间段为标题，缩略图帮助定位；当前帧副标签可显示前台应用，不把整段归属给一个应用。15 分钟是展示分组，不是对一期 10 分钟物理分段格式的改动；会话、显示器和时间回拨的拆分见实施计划。
- 隐私区间用通用锁形占位，不显示查看原图的行箭头，不提供查看被排除内容的入口。
- 详情突出回放画面，底部是同一段记录的缩略图时间轴与播放控件：上一帧、播放／暂停、下一帧、倍速。图片示例为 09:30–09:45 范围，暂停在 09:42:10，速度 20×；拟支持缩放和横屏。
- 最新未提交部分显示“最近记录整理中”，不把 writing 段当作已经可查看。
- 连接中断时隐藏记录内容，复用 Runweave 的重连流程；不以缓存提供离线浏览。区分 Runweave 连接断开与已连接但本机记录读取不可用；采集暂停不等同于已有记录不可查看。

## 手机接口与鉴权边界（已确认）

手机使用现有 Runweave APIClient、当前连接地址及访问凭据，向 Runweave Backend 请求记录列表、缩略图和原始画面。接口鉴权复用现有 Bearer 校验、令牌刷新及连接身份约束；经过既有隧道时继续遵循其鉴权，不开旁路。图片字节请求也必须经过鉴权，不能只保护列表而公开媒体目录。

建议链路为：Runweave iOS → 当前连接的 Runweave Backend（已有鉴权）→ 本机 ScreenJournal 只读适配层 → 已提交记录。

采集与存储继续由独立 Mac App 负责，Runweave 停止不会终止采集；手机远程查看则依赖 Runweave 在线。Backend 不取得采集生命周期的管理权，不把手机令牌转交给独立采集程序。二期实施计划确定通过同用户 Unix socket 访问 App 内只读服务，不增加手机需要管理的独立服务地址。

数据必须属于当前连接对应的 Mac。连接切换或登出时取消旧请求并清除页面内容，迟到图片不能显示在新连接中；当前连接所在机器没有 ScreenJournal 能力时显示不可用，不自动猜测另一台 Mac 的地址或共享其他连接的凭据。

图片中的“我的 Mac”是当前连接名称的占位，其箭头只代表已有 Runweave 连接选择。图片中的“重新连接”复用已有连接流程，不代表为记录服务新建配对体系。

## 两端共同的回放交互

本轮以 Dayflow 的截图序列回放为参考，替换上一版“只能打开单张截图”的方向。参照[回放界面源码](https://github.com/JerryZLiu/Dayflow/blob/730d6f84b919998158ff7fdab15e3f032f7d8135/Dayflow/Dayflow/Views/UI/MainView/ScreenshotSlideshow.swift)与[回放引擎源码](https://github.com/JerryZLiu/Dayflow/blob/730d6f84b919998158ff7fdab15e3f032f7d8135/Dayflow/Dayflow/Views/UI/MainView/ScreenshotSlideshowPlayback.swift)，本轮仅核查源码，没有执行 Dayflow 的界面验收。

- 大画面与胶片带是同一回放的两部分，不是独立的视频列表和图片列表。胶片带显示抽样预览，拖动可以定位缩略图之间的采样帧。
- 进入详情显示首个可用画面，默认暂停；按播放开始，支持 20×、40×、60×，首次默认 20×并记住后续选择。时间轴使用实际采集时间，不采用压缩 MP4 播放时长。
- 拖动时暂停，松开恢复之前的播放状态；上一帧／下一帧操作后保持暂停。播放到选定范围末尾停止，再次播放从头开始。
- 正常采样间隔内显示最近一张画面及其实际采集时间；隐私区间显示锁形占位，已知采集缺口显示无记录，不把前一张画面延续到缺口中。
- 按需解码一期已提交段中的截图序列，通过有界缓存和预取保证响应；默认不额外生成延时视频，不增加视频导出功能，也不需要模型生成活动卡片后才能查看。
- 回放范围在打开后固定；新记录通过刷新列表进入。只读取 ready 段，未提交部分保持“最近记录整理中”。
- 手机检测到断线后暂停并隐藏画面和胶片带；每 2 秒核验，超过 5 秒无有效确认即不可查看。重连后重新校验范围，以暂停状态恢复。连接切换、登出或数据过期时清除相应内容，不能靠预加载继续离线播放；远端容量删除的检测窗口见实施计划。

对应分期与技术缺口见[整体计划的二期回放章节](../../plans/2026-10-31-screen-recording-plan.md)。播放、暂停、倍速与拖动行为是实现目标；静态图片只能表达控件和布局，不能验证其工作正常。

## 状态范围

本次图片覆盖在线列表、回放暂停帧与控件、隐私占位、正在整理和离线。尚未绘制的必要反馈包括正在播放、拖动过程、回放中的缺口、当日无记录、图片已经过期、读取失败及尚未连接记录服务；不把这些状态伪装成加载中的普通图片。

## 功能分类与交付边界

产品核心设计：日期选择、记录列表、截图序列播放／暂停、三档倍速、缩略图时间轴、逐帧与时间定位、来源 Mac、隐私与过期状态、在线连接反馈。

原型辅助内容：画面外的设计板标题和三个状态名称；生成的示例数据与桌面缩略图。这些不进入产品 UI。

列表分组、详情缩放行为和手机菜单入口已在二期实施计划确定；具体视觉间距仍可在原生实现中微调。图片工具生成的细小图标及占位截图文字不作为精确的实现合同。

本轮只检查文档链接和图片产物，不启动采集、不读取个人屏幕记录、不启动模拟器、不声称完成交互验收。图片不需要运行命令，可直接打开 PNG；后续原生实现先验证 Mac 回放，再在 iOS 模拟器中通过 Runweave 已有鉴权验证真实数据链路。
