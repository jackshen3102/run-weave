> 历史设计原型。当前产品行为见[终端代码预览](../../architecture/terminal-code-preview.md)；数量与列表均最多 10 条，下方原型中的 14 条等计数仅为历史演示。原型截图不能代替产品验收。
> 设计评审产物，使用虚构提交演示，不代表当前产品已实现或真实仓库状态。当前处于原型评审阶段，未冻结。

## 启动

在仓库根目录执行：

```bash
python3 -m http.server 6188 --bind 127.0.0.1 --directory docs/prototypes/main-branch-updates
```

打开 <http://127.0.0.1:6188/>。手机端原型见 [手机原型说明](mobile/README.md)，访问 <http://127.0.0.1:6188/mobile/>。无需构建，不连接真实 Backend，不执行 Git 或同步代码。

## 原型简报

- 目标：根据远端默认主分支中当前工作区尚未包含的提交标题，判断是否需要同步。
- 动作与流程：点击工作区旁的 `main ↓14` → 打开 Preview 的“主分支更新” → 浏览最新 10 条 → 按需刷新。也可直接使用新增页签。
- 界面范围：桌面/Web 工作台的 Worktree rail 与 Preview，保留深色终端和原有 Preview 页签结构。窄视口仅供布局检查，不代表原生 iOS 设计。
- 状态：有差异、无差异、检查中、刷新失败保留旧结果；切换工作区后展示对应内容。
- 非目标：合并、rebase、cherry-pick、逐文件 Diff、完整 Git 分叉图、当前分支最近提交历史。

## 产品核心功能

| 元素 / 行为                        | 用途                          |
| ---------------------------------- | ----------------------------- |
| 点击现有主分支落后数量             | 进入所选工作区的更新视图      |
| Preview 内“主分支更新”页签         | 提供固定阅读空间              |
| 比较源与目标分支、差异总数         | 明确正在查看的差异范围        |
| 最新 10 个标题、短 SHA、作者和时间 | 帮助识别具体提交；不打开 Diff |
| 手动刷新与最后检查时间             | 区分成功结果与过期结果        |
| 无差异、刷新中及失败反馈           | 避免把失败或旧数据当成已同步  |
| 切换工作区、关闭/重开、展开/还原   | 融入现有工作台导航            |

`origin/main → 当前分支` 表示主分支提供、当前分支尚未包含的提交；不表达自动合并方向。真实实现应复用远端默认分支识别，不写死 main。

## 原型辅助功能

| 辅助内容                              | 触发方式                            | 边界                                      |
| ------------------------------------- | ----------------------------------- | ----------------------------------------- |
| 虚构工作区和提交                      | mock-state.json                     | 均为演示数据；14 条中只提供 10 条列表数据 |
| 初始 Changes 入口                     | `?view=changes`                     | 便于检查从数量提示进入的完整流程          |
| 无差异                                | 点击 main 工作区，或 `?state=empty` | URL 参数不进入产品                        |
| 旧结果                                | `?state=stale`                      | URL 参数不进入产品                        |
| 刷新失败                              | `?refresh=error` 后点击刷新         | 只模拟失败反馈，不执行网络 Git 请求       |
| 初始工作区                            | `?context=wt-2`                     | URL 参数不进入产品                        |
| 850ms 检查过程                        | 点击刷新                            | 演示时序，无真实 Git 操作                 |
| 终端、Changes、Explorer 和 Files 背景 | 静态界面                            | 为入口提供上下文，不是终端或文件工具实现  |

无默认可见的 mock 控制面板。

## 验证

使用仓库固定版本的 Playwright CLI 在独立原型页面上交互检查：工作区数量入口、10 条列表与总数、切换工作区、无差异、刷新、刷新失败保留旧结果、关闭/重开、展开/还原及窄视口布局。已通过 13 项真实浏览器交互检查（2026-10-26，Runweave Browser Profile 1 的独立原型标签页）；1440×1080 与 390×844 布局已检查。`pnpm docs:check` 和 `git diff --check` 通过。

## 设计记录与边界

- 当前采用：Preview 新页签，数量提示作为快捷入口；提交列表使用单列节点线辅助扫描，不绘制分叉图。
- 未采用：独立源码工具、完整 Git 图、直接跳转平台 Compare。
- 尚待用户评审：最终视觉、元数据密度、工作台侧栏宽度。未开始产品实现或实施计划。
- 真实代码现状：后端 `backend/src/terminal/git/home-branch-status.ts` 已获取默认主分支和落后数量，仍缺提交列表合同与接口。桌面数量提示在 `frontend/src/components/terminal/workspace/worktree-branch-status.tsx`，Preview 页签在 `frontend/src/components/terminal/preview/panel/shell.tsx`。
- 原型验证不证明真实 API、跨端、远程 Git 或代码同步行为已可用。
