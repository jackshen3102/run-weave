# 桌面与手机消息旁聊原型

2026-10-17 历史设计原型。当前版本已替换此前“旁聊继续使用终端画面”的方向：
原 Tab/终端页内进入消息旁聊，展示提问、等待状态和最终回答，返回保留会话。
这是设计模拟，不作为当前产品能力或验收证据；当前合同见[独立消息旁聊](../../architecture/terminal-state.md#独立消息旁聊)。

## 打开

在 Runweave 的 Prototypes 浏览器打开本目录；默认手机画面。
也可以在仓库根运行：

```bash
python3 -m http.server 6197 --bind 127.0.0.1 --directory docs/prototypes/mobile-side-chat
```

- [手机原型](http://127.0.0.1:6197/)；[桌面原型](http://127.0.0.1:6197/?surface=desktop)。
- 手机屏宽随视口铺满，桌面预览时以 393px 外框呈现；桌面原型包含项目、两个终端 Tab 和右侧 Browser。
- 当前实现以[终端架构](../../architecture/terminal-state.md#独立消息旁聊)和源码为准。原型页面中不放技术说明或切状态辅助按钮。

## 原型简报

目标：一边让主任务继续执行，一边就当前任务独立问答，手机和桌面使用相同导航及消息语义。

- 手机：浮动输入按钮左侧或主输入工具栏点击「旁聊」，进入整屏聊天页。
- 桌面：原 Codex Tab 原位显示「旁聊 · Codex」，顶部「返回主对话」恢复主视图。
- 旁聊持续显示普通聊天输入框，用户消息在右、最终回答在左；没有终端字符、命令栏、思考和工具输出。
- 来源条显示「主对话 · 第 12 轮」，可查看创建时来源轮次的文字预览；主任务状态独立显示。
- 发送后只显示「正在回答…」；完成后一次显示答案。停止保留已收消息和新草稿，主任务状态不变。
- 返回保留同一会话和草稿；后台完成显示本机新回复圆点。结束需要确认，再次进入创建新的旁聊。
- 手机和桌面的导航独立，消息同步。原主终端的 Tab、输入、草稿、运行状态和右侧布局保持各自归属。
- 上下文、消息正文等来源于 mock-state.json；真实继承完整模型上下文必须由后续原生 fork 验证。

本期原型的旁聊输入只有文字。主终端的附件、快捷键、排队、模型设置和回复辅助仅作现有界面参考，
不据此扩展到消息旁聊。主任务停止用于对照独立状态；此原型不能证明真实主进程或 WS 没有受影响。

## 交互和模拟存储

可以提问「这里的 generation 是做什么的？」或「重连怎么避免重复发送？」；答案为固定样例，
并不调用模型。2.2 秒延时模拟最终回复；任何 reasoning/tool 示例事件都不进入旁聊画面。

原型用带专属前缀的 localStorage 保存一个共享模拟旁聊和各客户端独立草稿，用 storage 事件模拟跨窗口同步。
同源两个窗口可以分别打开手机和桌面，停留在不同视图观察结果；它不证明服务器并发/事务/恢复正确。
模拟计时器由已打开页面驱动，关闭所有页面后没有后台模型服务；再次打开只根据样例时间收敛状态。
原主草稿保持该页内存。真实计划要求主归档维持既有行为，不能从原型刷新推断主归档实现。

URL 参数均为原型辅助，不进入产品 UI 或实施范围：

| 参数              | 用途                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| `surface=desktop` | 桌面外壳；省略为手机                                                 |
| `view=side`       | 打开消息页；`conversation` 补一轮样例；`returned` 展示返回且有新回复 |
| `scope=任意名字`  | 隔离模拟数据；两个视图相同 scope 共享模拟会话                        |
| `client=任意名字` | 区分测试夹具中的本地草稿，普通窗口默认自动区分                       |
| `send=reject`     | 模拟发送拒绝，保留草稿                                               |
| `send=unknown`    | 模拟结果不明，禁重复提交，提供只读查询入口                           |
| `reply=fail`      | 模拟生成失败，不生成假答案                                           |
| `offline=1`       | 禁用写入；`supported=0` 隐藏新入口                                   |

旧 `managed=0` 参数不再使用：新消息旁聊不以受管 TUI 控制标志决定能力。

## 功能分类

| 分类     | 内容                                                              | 后续实施           |
| -------- | ----------------------------------------------------------------- | ------------------ |
| 产品核心 | 两端入口、原 Tab 导航、聊天输入与最终答案、固定来源预览           | 是                 |
| 产品核心 | 返回/停止/结束分离，独立草稿/选区，新回复、失败/结果不明反馈      | 是                 |
| 产品核心 | 两端导航互不驱动，消息与当前生成状态共享                          | 是                 |
| 原型辅助 | localStorage/storage 事件、固定答案、模拟延时、URL 参数、手机外框 | 否                 |
| 周边参考 | 现有项目、工作区、Browser、附件与模型控件的静态外观               | 不增加对应产品流程 |

## 设计记录

采用：独立消息页、完整历史分支的计划方向、HTTP 提交/查询最终结果、两端独立导航。
已放弃：复用同一 TUI 当前显示 thread 的旁聊、从 tmux 字符流抽取答案、让手机驱动桌面主旁聊切换、
仅隐藏终端过程却沿用其输入/停止/恢复路径。
此前 26 项 HTML 检查属于旧方向，不再作为本版通过证据。此处仅保留历史原型，不描述后续产品实现状态。
