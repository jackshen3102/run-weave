## 原型简报

- 目标：监控围绕完整任务作判断；用户能够发现、纠正失准目标，并知道判断采用了哪版目标。
- 真实挂载点：已有终端右侧“长任务监控”面板，以及终端上方的监控状态条。保留现有项目区、终端、工具标签、续接额度、判定详情、历史判断和底部监听开关。
- 用户动作：编辑目标和完成条件；重新生成；查看当前与更新后的差异；采用后重新判断；查看用户授权和计划承接关系；查看历史版本。
- 主要流程：当前目标 → 编辑或重新生成 → 变更核对 → 采用并重新判断 → 显示新目标的结果。取消保留原目标；内容不变不新增版本。
- 关键状态：正常目标、目标待核对、生成中、生成失败、预览过期、重新判断中、离线、监听关闭。
- 非目标：产品实现、实际调用模型、真实计划读取、发送终端消息、更新或删除历史数据、完整 iOS 原生设计、实施计划。

## 当前界面适配

使用现有 slate 深色底、sky 操作色、小号字体、16px 面板内边距和分隔线。默认 440px 右侧面板，较窄桌面为 390–400px。编辑、来源、变更核对均在原面板中切换，固定底部操作区，正文独立滚动；保留关闭、展开以及状态条重新打开入口。

390px 与 320px 为 Web 面板窄宽度检查，**不是新增一套手机 UI，也不是原生 iOS 验收**。项目列表、工具标签和终端输出是周边静态上下文，只有本任务涉及的入口可操作，不重设计工作区导航。

## 交互取舍

1. 目标由任务描述、完成条件、范围约束组成；首屏显示目标和完成条件，约束可展开。
2. 人工修订与重新生成都先显示字段差异。生成依据可展开查看，避免用一条短句遮住多轮授权。
3. “继续”“现在进展如何了”沿用目标；“先别实现，只讨论方案”提供范围变更预览。用户明确缩小范围后，旧范围不再作为未完成义务。
4. 目标采用后递增版本，先将旧判断标为“上次判断”，等本轮结果返回后再显示最新判断。历史判断保留其原目标。修订目标本身不重置续接额度，新用户输入按现有规则重置。
5. 监听开关与本轮结果分离。完成、受阻或目标待核对不会关闭监听；目标待核对或重判期间暂不发送自动续接。
6. 正常明确的新要求应由最终产品自动更新目标；本原型将涉及范围替换的样例展示为可核对预览，具体自动更新边界仍待评审，不据此新增每轮强制审批。
7. 未采用：独立目标管理页面、把编辑变成全屏弹窗、最近一句覆盖全部目标、固定截取最后 N 条而丢弃早期授权、将评分表示为正确率。

## 演示数据与边界

样例参考本次实际检查的旁聊任务，已做节选、归纳和时间简化。`mock-state.json` 不是原始证据导出，不能据此评价原任务结果。

原型不调用模型，生成和判断使用固定样例。终端输入器仅演示本页状态变化，不向真实终端投递：

- 输入“继续”或“现在进展如何了”：保持当前目标和版本。
- 输入“先别实现，只讨论方案”：生成讨论方案的新范围预览。
- 手工把目标改为“仅修复并验证 Ctrl+/ 快捷键兼容性。”，并填写相应完成条件：样例已有该交付完成报告，重新判断展示“任务已完成”。
- 其他任意人工目标：展示等待新回复，不假装模型已验证任意文本。
- 在变更预览期间提交新的消息：预览过期，不能采用旧结果。

生成耗时、评分、判断、网络失败、冲突及续接保护均为交互样例；没有真实持久化、后台监听、跨端同步、审批或自动续接。原型不能验证实际分类准确率。

## 验证

2026-10-16 使用仓库固定的 `pnpm exec playwright cli`，经 Profile resolver 附着当前 Runweave Terminal Browser Profile 1，在新标签中完成 32 项交互检查，均通过：

- 失准目标的三字段生成、差异预览、取消、取消后的延迟结果隔离、采用与重判。
- 旧判断在重判期间明确标记、历史保留原目标、受阻保持监听。
- 空目标校验、缩小到快捷键任务后判断变为完成、“继续”保留人工目标、新用户消息重置额度。
- 内容无变化不产生版本、监听关闭和恢复、查看授权来源、关闭与状态条重开。
- 明确范围调整的预览、取消保留原目标、采用讨论范围。
- 生成失败重试、过期预览禁止采用并可重生成、离线禁用写操作。
- 1440×900 桌面；390×844 和 320×740 窄屏无横向溢出，编辑和核对的固定操作按钮可见。

控制台 0 error / 0 warning；JavaScript 语法检查与 `pnpm docs:check` 通过。未新增单元测试。检查脚本为本机一次性浏览器操作材料，未加入产品测试目录。
