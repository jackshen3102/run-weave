对应业务请求与服务端证据

桌面和手机均出现一个会话跨多个 launch；手机样本甚至跨构建版本。云端只发送固定阶段事件，不发送每次操作 ID；并发操作不能仅凭时间强行配对。终端 HTTP 输入沿用业务 operationId；其他链路逐条核验。Electron 主进程 launchId 与前端启动 ID 也不能直接当成同一个 ID。

指标必须绑定到业务含义

  • 使用证据：功能进入或操作开始，不等于成功。
  • 接受证据：confirmed / acknowledged 对终端仅表示接受或入队，不表示 Agent 完成任务。
  • 失败与未知：failed、unknown、cancelled、rejected 分开统计；未知不能自动算失败。
  • 连接生命周期：建立结果和建立后的关闭分别记录；19 个桌面操作先 confirmed 后 failed，2 个手机操作先 confirmed 后 cancelled，不能仅按最后状态算建立失败。
  • 阶段耗时：用同客户端同操作的 elapsedMs；手机样本的服务端时间早于客户端 started 163ms，时钟未校准前禁止跨端相减。

满足同环境、同版本、同窗口、按唯一操作去重且链路完整后，才计算“已知失败操作数 / 纳入观察的操作数”。同时披露未知、在途、取消和拒绝数量；窗口边界及记录截断单独处理。证据不足只报样本计数，不称总体失败率。

第一项交付：数据覆盖矩阵

真实样本已经给出了首版边界。

桌面 4 次发送有确认记录；手机 1 次发送以同 operationId 匹配到 Backend 派发，369ms 确认、402ms 记录 UI 更新。桌面也有建立前 failed 与建立后 failed 的不同样本。它们支持阶段分类，不代表已复现产品 Bug 或 Agent 任务完成。

每个来源记录：采集实现、实际部署、读取方式、最近可用时间、留存与截断、字段语义、关联键、样本范围。先补接入与归档；确实缺字段或事件时再提最小采集改动，保留现有脱敏与遮盖边界。

补采集清单：先接已有证据，再补确实缺的字段

  1. 首版直接复用：桌面操作环导出与手机 / 桌面短时合并诊断；后者已证明可按 operationId 对应正常发送，无需先加全量成功请求日志。
  2. 首版拟新增：JSON / JSONL 格式识别、字段归一化、操作阶段分类、脱敏归档、覆盖回执与去重台账。桌面 launchId 和手机 launch_id、数值字符串及 client 枚举需归一化，原始值仍保留。
  3. 自动采集前补：受控导出、有界归档、读取水位和丢弃计数；当前满环且有缺头，不能用每日定时掩盖覆盖丢失。
  4. 按需补关联：连接事故需要精确归因时补终端 / attempt 映射及关闭原因码；已有发送 operationId 复用，不把全量操作 ID 上传 Clarity。

桌面与手机导出已取得，无需重复提供。剩余缺口：手机本次发送的云端收录、桌面连接到服务端的精确映射、高负载留存覆盖。本轮仅更新方案，未修改采集设置。

04 / 最小落地范围

第一版，交付一个可用的工作流。

先验证真实问题能够被发现并持续跟踪，再扩展数据源与调度。

盘点已完成，先接两种真实文件

内容识别 JSON / JSONL，保留端、实例、构建与覆盖回执；以现有桌面和手机样本核对 ID 关联、连接阶段和缺头。Clarity 缺失单列，不阻断本地报告。

再跑一轮巡检

基于可用来源新增项目 Toolkit 技能与汇总脚本，手动运行并生成问题台账。行为异常与系统异常进入同一取证流程；采集缺口单列。

再跑一次

相同问题更新原记录；展示新增、持续、复发、待复验和覆盖缺口。验证重跑不重复建单，不把零日志当作已恢复。

最后接调度

沿用现有定时任务。明确机器、时区、时间、模型与授权范围后配置；调度执行目录独立，必须显式指向项目和台账。

首版拟新增产物

一个入口，三类记录

  • 技能入口：plugins/toolkit/skills/quality-workflow/
  • 每轮报告：本次范围、变化、影响和阻塞。
  • 问题台账：稳定问题 ID、首次/最近出现、状态、归因、修复版本、下一步。
  • 证据索引：来源、时间窗、脱敏摘录、原始位置和内容摘要；有限保存，避免日志轮转后无法追溯。

拟存于项目的 .runweave/quality-workflow/，不提交原始运行数据。多个 worktree 共用一个明确的台账目录，写入需要锁与原子替换；重跑用采集标识去重。

拟议归档默认：30 天或 100 MiB，先到先清理最旧非固定证据；未结问题必要证据固定保留，容量不足时报告阻塞。保存字段白名单，不复制输入片段的字符编码或原始正文。这是容量策略建议，尚未实施。

首版不新增产品页面、自动部署、Meego/GitHub 提单或飞书群推送。页面中的演示控件只服务本次方案评审。
