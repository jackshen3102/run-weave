# 快捷指令一键后台运行 SVG 原型

[点击前](index.svg)展示鼠标停在新增操作时的快捷指令弹出层；[点击后](running.svg)展示同一张卡片的运行反馈。点击卡片的“查看运行”进入[执行过程](progress.svg)；运行结束或从完成通知进入[运行结果](result.svg)。四张 SVG 可直接在浏览器或系统预览中打开。[预览 PNG](preview.png)对应点击前画面。

## 当前代码与设计落点

- 弹出层按 `frontend/src/components/terminal/input/quick-input-popover.tsx` 的 `w-[420px]`、搜索、固定/最近/全部标签和保存入口绘制；SVG 按 2 倍像素输出。
- 卡片按 `quick-input-row.tsx` 的标题、`line` 标签、原文、来源、时间和 3 列操作绘制。现有操作占了 5 个位置；新“后台运行”放在第二行空出的第三格，保留发送、插入、复制、固定和删除。
- 点击该操作后直接提交已保存的技能指令，卡片反馈“后台运行中 · 查看运行”，结束后按运行结果通知。模型与权限属于后台执行配置，不在每次点击时弹表单。界面不新增独立任务创建页。
- 运行开始后留在原卡片，不强迫跳转。“查看运行”打开同一条运行记录：进行中显示状态和持续更新的输出；结束后显示成功或失败状态、摘要、产物链接，仍能按需展开完整输出。通知直接定位到该记录；有问题或要追问时，才点“打开原对话并继续追问”进入普通终端。
- 查看记录应在关闭弹出层后仍可返回：重新打开快捷指令可从该卡片进入；通知也应带运行记录标识，打开同一视图。详情使用原弹出层的视觉语言，不增加创建表单。长输出区域滚动，不推高弹出层。
- 现有 `handleSend` 通过 `sendTerminalInput` 把文本送到活动终端；后台运行需独立提交，不能把已有发送动作换个图标后宣称脱离终端。已保存指令包含 `data`、`mode` 和项目上下文，真正执行时仍要由 Backend 校验目标、技能资格、权限和幂等。
- 现有定时任务代码已有 `RunProgress` 的运行输出读取、`RunSummary` 的结果摘要以及 `useOpenRun` 的原对话恢复。收敛后的实现直接复用同一 task/run 存储、队列和恢复接口，只补快捷指令接入、项目/worktree 快照和通知定位，不新增任务平台。

## 通知内容

通知首先回答“哪个项目／worktree 的任务结束了”。桌面通知和手机推送采用相同的信息顺序：

- 标题：`browser-viewer / wt-1 · 已完成`
- 正文：`创建 github pr · PR #123 已合并`（示例结果）
- 失败或需要介入时，标题改为 `browser-viewer / wt-1 · 失败` 或 `browser-viewer / wt-1 · 需要处理`，正文写任务名和简短原因。

有 worktree 时同时显示项目名和 worktree 名，避免不同项目的 `wt-1` 混淆；没有 worktree 时只显示项目名。名称过长时保留可区分的 worktree 部分。执行过程和结果视图也显示同一名称。

通知使用运行启动时保存的目标项目／worktree 信息，不能取用户收到通知时正在查看的项目。点击通知按该次运行标识打开原记录。项目名称是展示信息，不用它代替稳定的项目和运行标识。

## 范围

这是用于评审入口、过程与结果的静态 SVG。指令、运行状态、通知和结果均为示意，没有实际触发 GitHub PR。`result.svg` 中的 PR #123 是示例文本。当前接入边界见[架构索引](../../architecture/README.md#agent-系统)，行为验收见[快捷指令测试计划](../../testing/background-commands/core.testplan.yaml)。桌面自更新、独立 worker 和维护租约不属于当前接入范围。

原先的独立任务列表/创建弹窗方案已撤回。SVG 使用当前快捷指令组件的 slate 配色与布局；新增操作只占现有卡片空位。
