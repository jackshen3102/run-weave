Skill 管语义，工具管投递事实
当前 Agent 做什么
读取 Skill，查别名注册表，确认任务正文和引用范围；调用脚本派发，读取真实结果并归属到具体接收者。
多目标默认转发同一完整任务，不自行替接收者作答。明确分工应保留用户要求，不靠角色名猜任务。
派发工具做什么
固定目标身份、每个目标独立投递标识、并发提交、结果读取、去重与错误回执。判断依据是原生会话和执行状态。
先解析所有目标；未知别名不猜、不自动新建。不确定是否送达时不盲目重发。
独立会话意味着什么
每个接收者保留自己的会话和上下文。收到本次任务与显式引用，不默认获取发起者全部历史。
结果回到发起 CLI；单独 @ 某位只发给它。同一批次其他会话不被清空、切换或重启。
取舍：无需改 CLI 输入 UI，能复用 Skill 机制；代价是多一次当前 Agent 的理解与工具调用。自动触发有模型依赖，不能把一次成功当作稳定保证。需要明确触发时可显式调用 Skill，再写 @目标。


Review 落地后的通用阶段
后续通用层
  • 已有会话别名注册与查询。
  • 多目标派发，分别回执、分别读取结果。
  • 单目标追问沿用原会话。
  • 提交一次、同一投递不重复执行。
  • 等到结果后，在发起 CLI 分别报告。
单独设计和验收
  • 不等待结果时的异步通知与自动回报。
  • 忙时排队、人工接管与重启恢复。
  • 按角色新建 Agent、小组和跨机器。
  • 不同 CLI 的 Skill 触发与 @ 文件引用冲突。
  • 多人同时修改同一工作区的边界。
当前 rw terminal task 底座针对 Codex；通用别名层、生产级派发 helper 与跨执行器合同仍需补齐。探针里用户给请求编号是为了核对证据，正式使用应由工具持久化生成，不要求用户手填。
