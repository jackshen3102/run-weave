# 桌面终端一键回复原型

面向 Runweave 桌面 Terminal 的历史交互探索。它比较 iOS 固定回复“可以 / 继续 / 不需要”
迁移到桌面后的不同入口与布局；最终选定右侧快捷抽屉。原型不连接真实 Backend。

## 启动

```bash
python3 -m http.server 6188 --directory docs/prototypes/desktop-instant-replies
```

打开：

```text
http://127.0.0.1:6188/
```

若本机 `6188` 已被其他原型占用，可替换为任意空闲端口；本轮浏览器验证使用 `6418`。

## 文件

- `index.html`：第一轮底部回复栏原型。
- `app.js`：第一轮原型的一键回复、草稿和发送状态模拟。
- `concepts.html` / `concepts.js` / `concepts.css`：第二轮五种交互方向；通过 `variant`
  参数切换 `inline`、`composer`、`fan`、`rail` 和 `header`。
- `mock-state.json`：项目、Terminal 输出、固定回复和快捷指令样例。
- `concept-rail.png`：最终选定的右侧快捷抽屉方案。

## 原型简报

- 目标：让桌面 Agent Terminal 也能快速发送固定回复，同时保留当前草稿且不混入快捷指令库。
- 用户动作：展开一键回复、点击固定回复、观察发送状态与反馈、收起回复栏、继续编辑原草稿。
- 主要用户：在 Runweave 桌面端与 Codex、Trae、Pi 等 Agent 交互的用户。
- 影响的产品界面：Terminal surface 右侧中部和 floating composer。
- 关键流程：右侧入口 → 快捷抽屉 → 单次发送 → 成功或未确认反馈 → 继续使用抽屉或原草稿。
- 重要状态：收起、展开、发送中、发送成功、发送未确认、有草稿、不可用。
- 非目标：同步 iOS 本地回复库、编辑固定回复、替换现有快捷指令、连接真实 API。

## 选定交互

- 右侧中部以紧凑竖向入口进入，展开后显示与屏幕右边缘贴合的快捷抽屉。
- 抽屉内依次展示“可以”“继续”“不需要”，点击后直接提交，成功后抽屉保持展开。
- 回复发送中禁用抽屉按钮和 floating composer 提交动作；已有草稿保持原文。
- 抽屉与顶部“快捷指令”继续分离，固定回复不会进入快捷指令历史。

以下 URL 参数是原型辅助功能，不进入产品：

```text
?instant=closed
?composer=open&draft=请保留这段草稿
?replyResult=failure
?replyState=pending
?replyState=failure
?availability=unsupported
```

## 验证点

- 支持的桌面 Agent Terminal 可看到右侧入口，展开后显示三个固定回复。
- 回复入口与顶部“快捷指令”入口视觉和语义分离。
- 发送中三个回复按钮与 composer 提交动作同时禁用。
- 成功后抽屉保持展开；已有 composer 草稿保持原文。
- 失败状态显示“结果未确认”且不自动重发。
- 抽屉与 composer 同时出现时互不遮挡、不横向溢出。

## 功能分类

### 产品核心功能

| 元素 / 行为                    | 最终产品是否需要 | 产品价值                            | 备注                             |
| ------------------------------ | ---------------- | ----------------------------------- | -------------------------------- |
| 右侧中部一键回复入口           | 是               | 在 Agent 等待确认时快速打开固定回复 | 仅安全的桌面 Agent Terminal 展示 |
| “可以 / 继续 / 不需要”快捷抽屉 | 是               | 减少重复输入                        | 固定顺序，不进入快捷指令库       |
| 发送中全局输入锁               | 是               | 防止双击和并发输入                  | 回复与 composer 共用 pending 锁  |
| 成功反馈                       | 是               | 告知请求已被接受                    | 抽屉保持展开                     |
| 未确认错误                     | 是               | 避免网络结果未知时自动重发          | 保留草稿和抽屉                   |
| 草稿保留                       | 是               | 回复不消费用户正在编辑的内容        | 后续由用户显式发送               |
| 顶部快捷指令入口               | 是，现有能力     | 表达两类功能并存                    | 本轮不修改其产品行为             |

### 原型辅助功能

| 元素 / 行为        | 辅助验证什么                        | 为什么不进入产品                   | 备注                       |
| ------------------ | ----------------------------------- | ---------------------------------- | -------------------------- |
| URL 状态参数       | 直接打开失败、pending、不可用等状态 | 生产状态由 Terminal 和请求结果驱动 | 页面无可见 helper 控件     |
| 900 ms 模拟延迟    | 检查 pending 布局和禁用态           | 生产延迟来自真实请求               | 仅 `app.js` 使用           |
| 模拟 Terminal 输出 | 展示回复提交后的视觉反馈            | 生产输出来自 WebSocket             | 数据位于 `mock-state.json` |

## 调整记录

| 轮次 | 调整内容                                                 | 原因                             | 结果                |
| ---- | -------------------------------------------------------- | -------------------------------- | ------------------- |
| 1    | 新增独立消息闪电入口与底部回复栏                         | 避免把固定回复混入可编辑快捷指令 | 两类入口可同时辨认  |
| 1    | 回复栏与 floating composer 使用同一底部堆叠容器          | 需要展示草稿保留且避免遮挡       | 两者可同时打开      |
| 1    | 将失败和 pending 切换放进 URL 参数                       | 演示控件不应进入产品画面         | 默认截图只有产品 UI |
| 2    | 对比消息内联、composer、扇出、右侧抽屉和顶部弹层五种方向 | 第一轮底部回复栏交互未获采用     | 选定右侧快捷抽屉    |

- 最终采用的候选交互：Terminal 右侧中部入口与贴边竖向快捷抽屉；成功不自动收起。
- 未采用的方向：消息内联、composer 内嵌、右下扇出和顶部混合弹层。
- 产品核心功能清单：已确认并进入实现。

- 冻结状态：右侧快捷抽屉方案已确认。

- 验证日期：2026-09-26。

  “结果未确认”提示，以及 pending 时 4 个回复栏按钮、3 个 composer 按钮和输入框全部禁用。
- 浏览器控制台错误和警告均为 0。
- 截图未启用 URL helper 状态，不包含原型说明或演示控件。

## 边界

- 原型不连接真实 Backend，不证明 `prompt_replace`、Pane 定位或历史隔离已经通过运行验收。
- 原型不导入生产源码，实施时必须以当前 Frontend controller 和 Terminal 输入合同为准。
- 原型只展示安全 Agent Terminal；普通 shell、mobile monitor 和不可靠草稿镜像通过 URL 参数模拟隐藏入口。
- 原型辅助参数、模拟延迟和模拟 Terminal 输出不进入产品实现。

## 产品实现衔接

- 原型表达的产品行为：右侧入口、三条固定回复、单次发送、草稿保留、成功/未确认反馈。
- 需要进入产品实现的核心功能：README“产品核心功能”表中的新增能力。
- 不进入产品实现的辅助功能：URL 状态参数、固定模拟延迟和模拟 Terminal 输出。
- 前端落点：`instant-reply-rail.tsx`、`floating-composer.tsx`、
  `use-floating-composer-controller.ts`、`surface.tsx`。
- 后端与协议：复用现有 input route 和 `SendTerminalInputRequest`，不新增合同。
- 验收方式：配套 `docs/testing/terminal/runtime/desktop-instant-replies.testplan.yaml`，在真实 Dev Session
  renderer 中使用 `$toolkit:playwright-cli` 取证。
