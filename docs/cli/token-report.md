# Codex 执行用量报告

入口：[本地报告命令](../../scripts/token-report/cli.mjs)。独立读取本机 Codex JSONL，
不连接 Backend，不调用模型，不修改会话、项目代码或随记。需要 Node.js 和 Git。

```bash
pnpm token:report
pnpm token:report --cwd /path/to/project --days 7
pnpm token:report --since 2026-09-25
pnpm --silent token:report --days 30 --json > /tmp/token-report-30d.json
pnpm --silent token:report --since 2026-09-25 --json > /tmp/token-report.json
pnpm --silent token:report --since 2026-09-25 --case '<报告中的选择 ID>' > /tmp/token-case.json
```

默认读取最近 30 天全部已结束会话，范围是当前 Git 项目、已登记 worktree 及其子目录。
工作区已有的 `.worktree/` 子目录也在项目范围内；已经删除且位于项目目录外的 worktree 无法自动关联。
`--cwd` 可从项目子目录调用。报告不设会话数和单日志大小上限，逐份读取时间范围内
全部已结束的本项目会话，也纳入子 Agent 会话；日志提供父会话 ID 时单独标明。
仍在运行、其他项目、审批评估和无可用记录的会话分别计入排除数，
不能把纳入数当作发现率。

默认日志来源是 `$CODEX_HOME/sessions`、`$CODEX_HOME/archived_sessions`；未设置
`CODEX_HOME` 时使用实际 HOME 下的 `.codex`。`--sessions-dir` 可显式替换日志来源。
报告排除审批评估会话，纳入分叉和子 Agent 会话，但不擅自
把它们的用量归因或合并到父任务。没有自动语义拆任务。

## 统计口径

- 以相邻累计计数之差计入原生日志轮次，重复累计值只计一次；不重复加入缓存输入、推理输出。
- `--since` / `--days` 按用量事件时间过滤。窗口前的记录仅建立计数基线；跨边界请求无法进一步按时间分摊。
- 累计计数回退时不猜测回退点消耗，重建基线并标记覆盖缺口；缺失字段显示未知。
- 报告中的相关用量不是问题独占用量、浪费量、实际费用或可节省量。模型分析用量未运行时为 `null`。
- 文件流式读取；损坏记录、无法读取的目录、未关联轮次和缺失用量都有覆盖提示。
  工具输出扫描最多 64,000 字符，截断会提示；不读取图片和加密推理内容。
- JSON `schemaVersion: 2` 包含项目范围、扫描覆盖、会话、轮次、用量、候选疑点和日志行号。
  零会话报告仍合法；请检查 `scan.excluded`、`scan.skipped`，不要将其解释为零消耗。

## 候选疑点与按需分析

首批规则检测视口阻塞、导航拒绝、构建输入变化、审批拒绝、路径或转发错误、相同参数多次失败、
等待期间多次唤醒、上下文输入增长，以及用户对交付或验证状态的追问。
普通源码读取中的错误示例不作为运行时错误；轮询不作为重复失败。

规则只定位线索，不能证明错误由某个 Skill 引起，也不会凭“没有命中”判断没有问题。
代码、说明、Skill、流程、工具、环境和 Agent 行为均可以在复核时成为候选原因。
自由文本无法可靠自动判断“已合并但原工作区未同步”等完整因果，需按需分析证据。

`--case` 必须沿用生成报告时的项目和时间范围参数，输出该疑点附近的用户消息、工具调用与结果、
来源行号和分析请求。每段最多 1,800 字符，总材料最多 24,000 字符，截断显式标注。
这是材料提取限制，不是模型 Token 预算；具体模型预算尚未定义。
命令不会启动 Agent 或发起模型请求。把材料交给当前 Agent 后，分析仅针对这条疑点，
日志里的历史命令不能视为本次执行授权。模型调用与用量回收尚未接入。

输出对常见 Bearer、JWT、密码和 token 字段做基本遮盖，但不是完整的敏感信息分类器。
报告和证据仍属于本机项目材料，分享前应核对内容。

## 查看报告

全量报告只提供覆盖、用量和待核查线索；`task_complete` 只表示轮次结束，不表示用户目标
已经达成。判断优化价值时，需要核对原任务目标、最终验收结果和完整执行轨迹，再比较同类任务
在改动前后的成功率、耗时与按缓存类别计费的成本。当前没有自动成功标签或自动节省结论。
