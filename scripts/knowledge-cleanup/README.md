# 每日产品优化知识清理

本机 Stable 的定时任务通过 `delta.py` 读取已登记仓库的经验、自进化和成果收件箱。先用已认证的 `rw` 核对 Stable 连接、存储路径和仓库登记，再用 SQLite 只读连接比对索引和版本元数据。每轮只导出有变化的条目正文。任务使用原有 CLI 和 API 处置条目并核对结果。

部署时将 `delta.py` 安装到当前 Stable 配置根的 `knowledge-cleanup/`，权限为 `0700`。首次用最近一次成功全量审查的 `evidence/after-*.json` 执行 `seed`，已有进度时会拒绝覆盖。旧盘点产物只在迁移时使用。扫描失败会中止本轮取数。

`begin <batch.json>` 冻结本轮变更。`finish <batch.json> --decisions <decisions.json>` 要求每个变更键都有 `reviewed` 或 `deferred` 的处置记录和具体理由。写入前校验上一轮进度，使用文件锁和原子替换保存，避免过期运行覆盖已提交进度。暂缓项保留理由，版本有变化时再次出现。

脚本依赖 Stable 的本地 SQLite schema。首次迁移会读取经验的现有值以匹配已审版本。后续读取经验的行索引及其他来源的版本元数据。源码文件内容和证据可用性单独发生变化时，在所涉条目再次进入审查或专项审计时复核。收件箱投影可能滞后，处置前使用鉴权接口核对当前版本和可用性。
